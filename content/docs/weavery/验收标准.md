> QA 可直接据此写测试用例的可测试 checklist + 跨页生命周期流转图。

本文是 weavery 产品规格的收尾章节,把前面散落在功能文档里的"动作 → 预期"收拢为可执行的验收清单,并补充跨页面的业务生命周期流转图。依赖前三块基石:[[数据模型]](实体与字段)、[[权限矩阵]](角色 × 资源 × 操作)、[[异常与边界]](正常路径之外的处理)。本文分三部分:**核心业务流转图(全局视角)**、**分模块验收 Checklist(逐页可测)**、**全局验收项(跨功能通用)**。

## 第一部分:核心业务流转图

### 1. 文章生命周期

覆盖草稿 → 发布 → 编辑 → 删除 → 注销级联的完整状态流转,含 Remix 分支。状态字段对应 [[数据模型#文章 Post]] 的 `Post.status`(`draft` / `published` / `deleted`)。

```mermaid
stateDiagram-v2
    [*] --> 草稿: 新建 / 自动保存
    草稿 --> 已发布: 点发布 .is-done 变绿
    已发布 --> 草稿: 编辑 ?edit=1 顶部提示覆盖
    草稿 --> 已发布: 重新发布 覆盖原稿
    已发布 --> 已删除: 作者删除 二次确认 2.5s
    草稿 --> 已删除: 删草稿 me 直接 remove / drafts 二次确认
    已发布 --> 改编Post: 他人 Remix 带 source_post_id
    改编Post --> 已发布: 改编者独立发布
    已删除 --> [*]
    注销 --> 已删除: 冷静期到期级联 E2
```

> [!info] 关键约束
>
> - 编辑模式"保存即覆盖",无版本树(见 [[功能/AI写作工作台#编辑模式(改已发布文章)]])
> - Remix 产生独立新 Post,不阻塞原作者([[异常与边界#C1 两人同时 Remix 同一篇]])
> - 删除是软删除(`status=deleted`),非物理消失

### 2. AI 交互流程

工作台内"指令 → AI 处理 → 用户决策"的完整链路,含失败回退。AI 任何失败都不直接改写文档(见 [[异常与边界#A AI 相关异常]])。

```mermaid
flowchart TD
    A["输入指令<br/>斜杠命令 / 自由指令"] --> B{"匹配斜杠命令?"}
    B -->|是 润色/续写/标题/摘要| C["按模板生成 AI 回复"]
    B -->|否| D["走 custom 分支"]
    C --> E["AI 处理中 .log-pending 850ms"]
    D --> E
    E --> F{"成功?"}
    F -->|成功| G["返回修改建议气泡<br/>含 ai-meta 文件目标"]
    F -->|超时| H["A1 气泡显「AI 响应超时,点此重试」"]
    F -->|失败 5xx| I["A2 Toast「AI 暂时无法响应,请稍后重试」"]
    F -->|审核拦截| J["A6 应用按钮禁用 + Toast「该内容未通过审核」"]
    G --> K{"用户选择"}
    K -->|应用| L["写入文档 不可逆<br/>按钮变 .ai-ok 文案随操作"]
    K -->|忽略| M["气泡保留 消息从数组物理删除"]
    K -->|重新生成| N["取素材池下一条 游标步进"]
    N --> G
    H --> O["点重试 复用原指令"]
    O --> E
```

> [!important] 应用是不可逆的
> 点"应用"后三按钮永久替换为 `.ai-ok`,无法撤销(见 [[功能/AI写作工作台#应用后状态]])。素材池游标持久化到 `localStorage["zd-wb-step"]`。

### 3. 通知生命周期

事件触发 → 通知生成 → 未读 → 筛选查看 → 标已读。AI 助手通知走特殊路径(带 AI 标签)。

```mermaid
flowchart LR
    E1["赞 / 收藏"] --> N["生成 Notification"]
    E2["评论 / 回复"] --> N
    E3["Remix 改编"] --> N
    E4["关注"] --> N
    E5["@AI 助手 评论<br/>summon_ai=true"] --> NAI["AI 评论通知<br/>带 AI 标签"]
    N --> U["未读<br/>红点 + 加粗"]
    NAI --> U
    U --> F["五 Tab 筛选<br/>全部/赞与收藏/评论/关注/Remix"]
    F --> R["点击查看 → 标已读"]
    R --> Z["未读数 -1"]
    Z --> ALL{"全部已读?"}
    ALL -->|是| DONE["page-sub 显「全部已读」<br/>按钮 disabled"]
    ALL -->|否| U
```

> [!info] AI 通知归属
> @AI 助手的评论通知归在「评论」Tab,用 `ai-tag` 视觉区分,**无独立 Tab**(见 [[功能/社交互动#通知文案模板]])。

### 4. 关注关系与信息流

关注 → 互关判定 → 取关,以及对信息流"关注"Tab 和通知的影响。

```mermaid
flowchart TD
    S["点关注按钮<br/>防抖 300ms"] --> Q{"对方已关注我?"}
    Q -->|否 单向| F1["建立 Follow<br/>对方进我关注列表"]
    Q -->|是 互关| F2["建立 Follow + 互关标记"]
    F1 --> NF["被关注方收到关注通知<br/>前提 notify_on_follow=开"]
    F2 --> NF
    F1 --> FEED["对方作品进信息流「关注」Tab"]
    F2 --> FEED
    FEED --> DM{"互关?"}
    DM -->|是| DMOPEN["私信准入不受 dm_open 限制"]
    DM -->|否 单向| DMGUARD["私信受接收方 dm_open 控制"]
    UN["点取关"] --> REM["Follow 关系移除<br/>对方作品从「关注」Tab 消失"]
```

> [!warning] 关注列表可见性
> 受 `settings.privacy.hide_following` 控制,开启后他人访问 `/users/:id/following` 返回 403 或空(见 [[权限矩阵#3 关注列表可见性]])。

### 5. 私信流程

发起 → 隐私限权检查 → 会话往返,含 AI 作者会话差异。

```mermaid
flowchart TD
    START["从作者主页点「私信」"] --> CHECK{"后端校验接收方<br/>dm_open"}
    CHECK -->|dm_open=true 任何人可发| OK["创建 / 复用会话"]
    CHECK -->|dm_open=false 且互关| OK
    CHECK -->|dm_open=false 且非互关| REJ["拒绝<br/>Toast「仅互关可发私信」"]
    OK --> SEND["消息往返<br/>气泡 + 按天分隔 + 正在输入"]
    SEND --> AI{"会话方是 AI 作者?"}
    AI -->|否 人类| HUMAN["正常 IM 体验"]
    AI -->|是 云小织等| AICONV["AI 会话差异<br/>带 AI 胶囊 / 头像 云<br/>话术提及工作台"]
```

> [!important] 后端必须校验
> 私信准入由**后端**在创建会话时校验接收方 `dm_open`,前端拦截仅为体验优化(见 [[权限矩阵#1 私信限权]])。
