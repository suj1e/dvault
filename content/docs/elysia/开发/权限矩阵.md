# 权限矩阵

## 设计理念

V1 没有账户体系，因此没有传统的 RBAC 权限模型。

V1 的"权限"基于：
- **Device 归属**：用户只能访问自己 Device 上的 Workspace 和 Session
- **本地文件系统权限**：macOS 遵循系统文件权限
- **用户主动操作**：Agent 执行前需要用户确认（某些操作）

---

## 操作权限

### macOS

| 操作 | 需要确认 | 说明 |
|------|---------|------|
| 读取文件 | ❌ | Agent 可以自由读取 Workspace 内的文件 |
| 写入文件 | ❌ | Agent 可以自由写入 Workspace 内的文件 |
| 执行命令 | ❌ | Agent 可以自由执行命令（限于 Workspace 目录） |
| 删除文件 | ❌ | Agent 可以删除 Workspace 内的文件 |
| 访问 Workspace 外 | ❌ | V1 限制 Agent 在 Workspace 目录内操作 |

**V1 安全措施**：
- Agent 的文件操作限制在 Workspace 目录内
- 命令执行限制在 Workspace 目录的 shell 中
- 不提供访问 Workspace 外的 API

### iOS

| 操作 | 需要确认 | 说明 |
|------|---------|------|
| 查看 Session | ❌ | 只读访问 |
| 发送消息 | ❌ | 向 Agent 发送指令 |
| 停止 Agent | ❌ | 停止当前执行 |
| 修改文件 | ❌ | iOS 不提供文件修改能力 |

### Web

| 操作 | 需要确认 | 说明 |
|------|---------|------|
| 查看 Session | ❌ | 只读访问 |
| 发送消息 | ❌ | 向 Agent 发送指令 |
| 停止 Agent | ❌ | 停止当前执行 |
| 修改文件 | ❌ | Web 不提供文件修改能力 |

---

## 用户介入点

V1 中，用户可以在以下时机介入：

| 时机 | 用户操作 | 结果 |
|------|---------|------|
| Agent 执行中 | 点击「停止」 | Agent 立即停止，Session 状态变为 stopped |
| Agent 执行失败 | 查看错误信息 | Agent 自动 Retry 或等待用户决策 |
| Agent 请求确认 | 查看 Agent 提议 | 用户选择继续 / 停止 / 修改指令 |
| Agent 完成任务 | 查看结果 | 用户确认完成或继续追加任务 |

---

## V1 不做权限控制

以下权限功能 V1 不做：

- [ ] 用户注册 / 登录
- [ ] 角色分配（Admin / Member / Viewer）
- [ ] Workspace 共享
- [ ] Session 共享
- [ ] 操作审计日志
- [ ] 文件访问控制列表（ACL）
- [ ] 命令白名单 / 黑名单

**原因**：V1 是个人产品，不涉及多人协作。权限控制在 V1 之后考虑。

---

## 数据隔离

| 维度 | V1 隔离方式 |
|------|------------|
| Device 之间 | 完全隔离，不共享数据 |
| Workspace 之间 | 完全隔离，Agent 只能访问单个 Workspace |
| Session 之间 | 完全隔离，Session 之间不共享状态 |
| 用户之间 | V1 不涉及多用户 |

---

## 安全考虑

| 风险 | V1 措施 |
|------|--------|
| Agent 误删文件 | 文件操作限制在 Workspace 内 |
| Agent 执行危险命令 | V1 不限制命令，用户自行负责 |
| 代码泄露 | 代码不上传到云端执行 |
| 未授权访问 | Device 即身份，物理设备访问即授权 |

---

> [!note] V1 安全哲学
> V1 采用"本地执行 + 物理设备即身份"的安全模型。代码不离开用户机器，Agent 在本地执行，用户对自己的设备有完全控制权。
