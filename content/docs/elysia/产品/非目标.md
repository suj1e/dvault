# Non-goals

本文档记录 V1 明确不做的功能、平台和场景。

这是产品决策，不是技术限制。以下全部是"现在不做"，不代表"永远不做"。

---

## 功能 Non-goals

### Multi-Agent

**不做**。V1 只有单个 Agent 执行单个 Task。

多 Agent 协作涉及复杂的状态管理、任务分配、结果合并，会在 V1 之后考虑。

### MCP（Model Context Protocol）

**不做**。V1 不引入外部工具协议。

V1 只使用内建的 5 个 Tool。MCP 可以作为后续扩展机制，但不是 V1 需求。

### Skills Marketplace

**不做**。V1 不开放 Tool 扩展市场。

Agent 能力由平台定义，不由用户安装插件。

### RAG（检索增强生成）

**不做**。V1 不建立代码库的向量索引。

Agent 通过 `search_code` 直接搜索代码，不做语义索引。

### 长期 Memory

**不做**。V1 不保存 Agent 的跨 Session 记忆。

每个 Session 是独立的。Agent 不会"记住"上一个 Session 做了什么。

### Subagents

**不做**。V1 没有子 Agent。

一个 Session 只有一个 Agent，所有工作由这个 Agent 线性完成。

### 复杂 Workflow

**不做**。V1 没有可视化编排、条件分支、并行任务。

Agent Loop 是线性的：Understand → Plan → Act → Observe → Verify → Complete / Continue。

### 自动部署

**不做**。V1 不自动部署代码。

Agent 可以修改代码、运行测试，但不会自动部署到生产环境。

### CI/CD 集成

**不做**。V1 不连接外部 CI/CD 系统。

Agent 可以运行本地测试，但不会触发 GitHub Actions 或类似系统。

### 代码 Review

**不做**。V1 不做代码 Review 流程。

Agent 修改代码后，由用户自行 Review。Agent 不提供 Review 功能。

### 多人协作

**不做**。V1 不支持多人同时操作一个 Workspace 或 Session。

每个 Device 独立，Session 可以多端查看但不支持多人同时编辑。

---

## 平台 Non-goals

### Linux Execution Node

**不做**。V1 只支持 macOS 作为 Execution Node。

Linux Server 支持在 V1 之后考虑。V1 的核心是多端体验，不是多端执行。

### Windows 支持

**不做**。V1 不开发 Windows 客户端。

Windows 用户可以通过 Web UI 使用。

### Android 支持

**不做**。V1 不开发 Android App。

移动端只做 iOS。

### WebView 套壳

**不做**。macOS 和 iOS 都必须是原生 App。

**禁止**使用 WebView 实现 macOS 或 iOS App。

### 云端执行沙箱

**不做**。V1 不在云端执行代码。

代码操作在用户本地执行。云端只做 Session 状态同步和 Event 转发。

---

## 商业 Non-goals

### 账户系统

**不做**。V1 不要求用户注册或登录。

设备即身份。用户直接使用，无需账户。

### 计费 / 订阅

**不做**。V1 不涉及付费功能。

V1 是免费产品，后续商业化策略不在 V1 范围内。

### 企业权限体系

**不做**。V1 不开发团队管理、角色权限、SSO 等功能。

### 用户管理

**不做**。V1 不开发用户 Profile、设置同步、偏好管理等。

### API 开放平台

**不做**。V1 不提供公开 API。

---

## 为什么这些不做

V1 的核心目标是：

> **一个真正能动手改代码的 Coding Agent，三端可访问。**

所有 Non-goals 的共同特征：它们要么增加了复杂度但没有直接服务于闭环，要么可以在形成闭环之后再通过更新添加。

V1 的时间应该花在：
1. Agent Runtime 的稳定性
2. 三端体验的一致性
3. Event System 的实时性
4. Tool Execution 的可靠性

而不是花在：
- 设计插件系统
- 实现云端沙箱
- 构建账户体系
- 规划商业化

---

> [!warning] 一个常见的陷阱
> "先做了，后面再删" 是产品设计的毒药。每一个 Non-goal 都应该被**主动拒绝**，而不是"来不及做"。
