# 权限矩阵

> 把散落在各功能文档里的权限规则,收拢成一张统一的「角色 × 资源 × 操作」矩阵,前后端据此实现访问控制。

weavery 的权限分两层:**页面访问权**(auth gate,见 [[全局规范#登录态机制]])和**操作权**(资源级,贯穿创作、互动、社交、治理)。前者决定能否进入某个页面,后者决定进入后能对资源做什么。本文把两层一并铺开,并梳理出需要后端动态校验的特殊规则。

> [!info] 符号约定
> 矩阵中使用三种标记:**✓** 允许 / **✗** 禁止 / **▸** 条件允许(在备注或专章里展开)。下文所有矩阵共用此约定。

## 角色

weavery 共 4 种角色,按"是否登录"和"是否对资源拥有所有权"两个维度划分。

| 角色                 | 标识                | 说明                                                                                                                |
| -------------------- | ------------------- | ------------------------------------------------------------------------------------------------------------------- |
| **游客 Guest**       | 未携带 Bearer Token | 可浏览公开内容(feed / post / profile / topic / search / guidelines / help),任何写操作都被拦截并提示"登录后即可使用" |
| **登录用户 User**    | 已登录的普通用户    | 携带有效 token,可执行所有登录态操作(创作、互动、社交)                                                               |
| **资源所有者 Owner** | User 的叠加态       | 对"自己的"文章 / 评论 / 草稿 / 资料 / settings 享有额外操作权;按 `resource.author_id == current_user.id` 判定       |
| **管理员 Admin**     | 社区治理执行者      | 删除违规内容、限制功能、封禁账号、处理申诉;原型无 UI,由 [[功能/账户与治理#执行与申诉]] 隐含                         |

> [!note] 关于管理员角色
> 管理员角色为**推断**——[[功能/账户与治理#执行与申诉]] 提到"我们通常按以下方式处理违规",隐含存在执行者。原型未体现管理后台,开发时需确认管理员账号的产生方式、管理界面与审计日志(见 [[待确认问题]] 相关条目)。

## 特殊权限规则

下列规则无法用静态矩阵表达,需要后端动态校验。

### 1. 私信限权

能否给某人发私信,取决于**接收方**的 `settings.privacy.dm_open` 设置,而非发送方。

| 接收方设置        | 发送方   | 结果                       |
| ----------------- | -------- | -------------------------- |
| `dm_open = true`  | 任何人   | 允许                       |
| `dm_open = false` | 互相关注 | 允许                       |
| `dm_open = false` | 非互关   | 拒绝,toast"仅互关可发私信" |

> [!important] 校验位置
> 私信准入必须由**后端**在创建会话时校验接收方的 `dm_open` 状态,前端拦截仅为体验优化。参见 [[功能/账户与治理#隐私]]、[[功能/社交互动#隐私控制]]。

### 2. 编辑 / 删除文章

仅当 `post.author_id == current_user.id` 才允许编辑 / 删除。前端 `?owner=1` 只是 UI 开关(控制编辑 / 删除入口的显隐),**后端必须按作者身份兜底校验**。

> [!warning] 纯前端无校验
> 原型中 `?owner=1` 是纯前端判断,任何人加该参数都能看到入口(虽实际删除仍需后端兜底)。详见 [[待确认问题#Q15]]。编辑跳 `create?edit=1` 覆盖原稿;删除二次确认 2.5s(见 [[功能/帖子详情与Remix#删除二次确认机制]])。

### 3. 关注列表可见性

受 `settings.privacy.hide_following` 控制。开启后,他人访问 `/users/:id/following` 应返回 403 或空列表,只有本人可看自己的关注 Tab。管理入口见 [[功能/创作者中心#我的]]。

### 4. AI 训练授权(数据使用权限)

`settings.privacy.ai_training_consent = false` 时,该用户的**公开内容不进训练集**。这是数据使用层面的权限,不影响内容的公开可见性。

> [!important] AI 伦理
> 这是 weavery AI 伦理的体现——把数据使用权交给用户。默认开启(贡献训练数据),用户可随时关闭。详见 [[功能/账户与治理#隐私]]。

### 5. AI 作者账号权限

云小织等 AI 作者是一种特殊账号:

- ✓ 可被关注
- ✓ 有 profile([[功能/作者主页]])
- ✓ 可收通知
- ▸ 能否被私信 / 被 Remix:**待确认**(参见 [[待确认问题#Q19]] 关于 AI 作者徽章的相关讨论,AI 作者会话差异见 [[功能/社交互动#AI 作者会话]])

### 6. 话题发帖

任何登录用户可在任何话题下发帖;发帖归属话题靠 `topic_id` 关联。原型中话题页发帖按钮未透传话题标签,见 [[待确认问题#Q7]]。

### 7. 注销冷静期

注销后 **30 天内数据保留**,可恢复;过期永久删除(级联删除文章 / 评论 / 草稿 / 关注关系等)。注销入口见 [[功能/账户与治理#危险区]]。

## 隐私设置 → 权限影响映射表

把 settings 隐私页的每个开关,映射到它影响的权限 / 操作。

| 设置开关(privacy)                                | 默认 | 影响的操作                                  |
| ------------------------------------------------ | ---- | ------------------------------------------- |
| 私信谁都可以给我发(`dm_open`)                    | 开   | 私信准入(见特殊规则 1)                      |
| 被关注时通知我(`notify_on_follow`)               | 开   | 是否生成"关注"通知                          |
| 在他人主页隐藏我的关注列表(`hide_following`)     | 关   | `/users/:id/following` 可见性(见特殊规则 3) |
| 允许用我的公开内容训练 AI(`ai_training_consent`) | 开   | 内容是否进训练集(见特殊规则 4)              |
| (导出 / 注销非开关,是动作)                       | —    | 见账号与资料类矩阵                          |

> [!info] 参见
> 隐私页完整字段与默认值见 [[功能/账户与治理#隐私]]。

## 鉴权实现要点(给后端)

- **Bearer Token 中间件**:解析请求头 `Authorization: Bearer <token>` → 校验 → 注入 `current_user`;无 token 或 token 无效即视为 Guest。
- **资源所有者校验**:加载资源 → 比较 `author_id` / `user_id == current_user.id`;不匹配则拒绝。
- **401 与 403 区分**:强登录页 / 登录态操作未带 token → **401**(未认证);带了 token 但无权操作他人资源 → **403**(无权限)。前端据此决定跳 `auth.html` 还是 toast 提示。
- **隐私设置动态校验**:私信准入、关注列表可见性需**查接收方的** `settings.privacy`,而非当前用户的。
- **AI 训练授权**:训练管道在拉取内容时,过滤 `ai_training_consent = false` 的用户作品。
- **管理员鉴权**:管理员标记需在 token claims 中体现(如 `role: admin`),治理接口必须二次校验该 claim。
