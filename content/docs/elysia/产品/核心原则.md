# 产品原则

## Principle 1 — Agent First

产品核心是 Agent，而不是聊天 UI。

Agent 不是聊天机器人的"附加功能"，而是产品的核心。UI 服务于 Agent 的可见性和可控性，而不是反过来。

**体现**：
- Session 页面的核心是 Agent Activity，不是聊天记录
- Tool Execution 是主要信息单元，不是消息气泡
- Diff 和 Terminal Output 是核心内容，不是附属信息

---

## Principle 2 — Execution Is Real

Agent 必须真正能够操作 Workspace 并验证结果。

Agent 不是"建议代码"，而是"修改代码"。不是"告诉你怎么修"，而是"帮你修完并验证"。

**体现**：
- Agent 可以读写文件、执行命令
- Agent 必须运行测试验证结果
- Agent 的每一步操作都是真实的文件系统操作
- 用户可以信任 Agent 的结果（因为 Agent 自己验证过）

---

## Principle 3 — Native Clients

macOS 和 iOS 都必须是原生 App。

禁止 WebView 套壳。原生 App 才能提供：
- 本地文件系统访问
- 本地终端执行
- 原生性能体验
- 系统级集成

**体现**：
- macOS：Swift + SwiftUI
- iOS：SwiftUI
- Web：独立 Web UI，不是 App 的 WebView

---

## Principle 4 — One Session, Multiple Clients

同一个 Session 可以被 Web、macOS、iOS 共同观察和控制。

这是产品的重要差异点。用户可以在 Mac 上启动 Agent，在 iPhone 上查看进度，在 Web 上回看历史。

**体现**：
- Session 状态在服务端统一维护
- Event System 实时同步给所有客户端
- 用户在任意端发送的消息都进入同一个 Agent
- 三端 UI 保持一致的信息架构

---

## Principle 5 — Device Is First-class

Execution Device 是产品模型中的正式概念。

不是"用户在某个平台使用"，而是"用户拥有 Device，Device 有 Workspace，Workspace 有 Session"。

**体现**：
- 用户首先看到的是「我的设备」
- Device 有状态（online / offline）和能力（文件系统、终端）
- Session 属于 Device + Workspace
- iOS 选择 Device 再进入 Session

---

## Principle 6 — Protocol Before UI

客户端不应该拥有自己的 Agent 状态模型。

Agent / Session / Event 的核心模型应该统一。客户端只是不同的"显示器"。

**体现**：
- 三端使用相同的数据模型
- 状态变更通过 Event 传播，不是客户端各自查询
- 新增客户端（如未来 Linux 桌面端）不需要重新设计状态管理
- UI 差异只是"怎么看"，不是"怎么存"

---

## Principle 7 — V1 Must Be Small

优先实现一个真正工作的完整闭环，而不是堆功能。

V1 的成功标准不是功能多少，而是"用户能否用 Elysia 真正完成一个 Coding Task"。

**体现**：
- V1 只有 5 个 Tool
- V1 只有单 Agent
- V1 不做 Memory、不做 MCP、不做 Plugin
- V1 只做 macOS 作为 Execution Node
- V1 的文档比代码更重要（先把产品定义清楚）

---

## 原则之间的关系

```text
Agent First（核心）
    ↓
Execution Is Real（验证）
    ↓
One Session, Multiple Clients（体验）
    ↓
Device Is First-class（模型）
    ↓
Protocol Before UI（架构）
    ↓
Native Clients（实现）
    ↓
V1 Must Be Small（约束）
```

Agent First 是起点，Execution Is Real 是检验标准，One Session Multiple Clients 是差异化体验，Device Is First-class 是产品模型，Protocol Before UI 是架构要求，Native Clients 是技术实现，V1 Must Be Small 是约束条件。

---

> [!important] 原则的优先级
> 当原则之间冲突时，优先级从高到低：
> 1. Agent First
> 2. Execution Is Real
> 3. Protocol Before UI
> 4. One Session, Multiple Clients
> 5. Device Is First-class
> 6. Native Clients
> 7. V1 Must Be Small
