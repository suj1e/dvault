## Q1

**铃铛未读数硬编码**

顶栏铃铛 `aria-label="通知,3 条未读"` 写死,但浮窗通知列表里实际只有 2 条 `.is-unread`,文案与数据不一致。

- 涉及:全站顶栏(见 [[全局规范#全站顶栏]])
- 影响:屏幕阅读器播报错误的未读数;真实数据下计数不可信
- 建议:未读数应由通知列表数据驱动,不硬编码

## Q2

**数字单位"万"与"k"混用**

同一站点内两套数字格式并存:卡片浏览数 / 点赞数用"万"(`fmt()` 规则 ≥10000 → "X.X 万"),而讨论统计(`discuss-stats`)、侧栏话题热度、推荐作者粉丝数用"k"(如 9.6k / 12.4k)。

- 涉及:全站(见 [[全局规范#数字格式化]])
- 影响:单位不统一,读者需心算换算;i18n 与统计口径混乱
- 建议:统一为一种单位制(中文社区建议统一"万"),或按语境明确分工

## Q3

**⌘B 加粗未实现**

工作台文档区工具栏提示"支持 Markdown · ⌘B 加粗",但全页 `keydown` 只绑定了 ⌘K 聚焦搜索,没有捕获 ⌘B,也没有对选区做 `**` 包裹的逻辑。

- 涉及:[[功能/AI写作工作台#文档区工具栏]]
- 影响:快捷键承诺与实现不符
- 建议:M1 明确——要么实现 ⌘B 包裹,要么移除提示文案

## Q4

**工具栏格式按钮无交互**

文档区工具栏 6 个按钮(加粗 / 斜体 / 引用 / 无序列表 / 链接 / 插图)都是裸 `<button>`,无 `click` handler,富文本格式化在原型里纯视觉占位。且缺有序列表、标题、代码块、分割线、撤销/重做。

- 涉及:[[功能/AI写作工作台#文档区工具栏]]
- 影响:开发时若按原型照搬,格式化全部不可用
- 建议:明确工具栏 M1 范围(是否实现 Markdown 包裹式格式化、按钮全集)

## Q5

**斜杠命令无弹出菜单**

工作台系统消息写"输入指令或点击下方 /命令",暗示存在可点击的命令芯片,但 HTML 里没有任何命令入口。输入 `/` 不会弹出建议列表,只对消息首 token 做全等匹配(`/润色` `/续写` `/标题` `/摘要`)。

- 涉及:[[功能/AI写作工作台#斜杠命令]]
- 影响:引导文案与 UI 不符;无自动补全体验
- 建议:二选一——补充斜杠命令弹出菜单,或修改引导文案去掉"点击下方 /命令"

## Q6

**模型清单不一致**

工作台 `MODELS = ["GPT-4o", "Claude 4", "DeepSeek-V3", "通义千问"]`,设置页个性化默认模型选项为"GPT-4o / Claude 3.7 / 本地模型 · 仅限已配置"。两处模型名与集合都不一致。且工作台是循环点击 pill,设置页是 select 下拉。

- 涉及:[[功能/AI写作工作台#写作配置]] · [[功能/账户与治理#个性化]]
- 影响:同一产品两套模型清单,用户困惑;数据契约无法对齐
- 建议:统一模型清单(名称与版本),明确工作台与设置页的选项关系

## Q7

**话题发帖未透传话题标签**

话题页"发帖"按钮 `location.href = "create.html"`,没有带上 `?t=` 参数,工作台不会预填该话题标签。文档曾描述"发帖预填话题标签"。

- 涉及:[[功能/话题与搜索#话题页]]
- 影响:从话题进入发帖无法自动归属话题,需手动补标签
- 建议:发帖按钮透传 `create.html?t={话题}`,工作台识别并预填

## Q8

**话题排序对"万"单位失真**

话题页"讨论最多"排序用 `parseInt(views)` 比较,但浏览数可能是"1.2 万"格式,`parseInt` 得到 1,导致排序错误。

- 涉及:[[功能/话题与搜索#话题页]]
- 影响:按讨论量排序结果错误
- 建议:排序前统一把"万/k"还原为数值再比较

## Q9

**空话题无空状态 UI**

`职业成长 / 生活 / 翻译 / 写作 / 生成式设计` 5 个内置话题 `posts` 为空,但话题页未提供空状态,会渲染空白列表。

- 涉及:[[功能/话题与搜索#话题页]]
- 影响:进入空话题看到空白,无引导
- 建议:补充话题空状态(如"这个话题还没有内容,去工作台写第一篇")

## Q10

**移动端侧栏直接消失无降级**

`<1020px` 时 `.sidebar { display: none }`,话题页的"相关话题""话题规则"、feed 页的侧栏在平板/手机上完全消失,没有移到底部或折叠的降级方案。

- 涉及:[[功能/话题与搜索]] · [[功能/信息流]]
- 影响:窄屏丢失话题规则等治理信息与发现入口
- 建议:移动端把关键侧栏内容(话题规则、热门话题)降级到正文流中或可展开抽屉

## Q11

**话题数实为 19,旧文档记 17**

原型内置话题实为 **19 个**,旧文档记为"约 17",且把"开源与商业化"误写为"开源商业化"。补全时已修正为 19 并核对名称。

- 涉及:[[功能/话题与搜索#内置话题]]
- 状态:**文档已修正**(见话题完整清单表)
- 建议:开发时以 19 个为准,数据源核对名称

## Q12

**草稿删后累计字数不联动**

草稿箱删除一条草稿后,`updateStats()` 重算了"全部草稿""AI 辅助创作"两项,但"累计字数"(`stat-words`)未重算。

- 涉及:[[功能/创作者中心#草稿箱]]
- 影响:删稿后累计字数错误
- 建议:统计联动应覆盖全部三项

## Q13

**草稿载入路由不一致**

me 页内嵌草稿的"继续编辑"跳 `create.html`(无参数),drafts 页跳 `create.html?draft={id}`。两处载入草稿的路由不统一。

- 涉及:[[功能/创作者中心#我的]] · [[功能/创作者中心#草稿箱]]
- 影响:me 页进入无法恢复具体草稿
- 建议:统一为 `?draft={id}`,me 页草稿行也带 id

## Q14

**help 实为完整 FAQ(旧文档误记为占位)**

help 页实际有完整内容:5 个分类共 13 条 FAQ(快速上手 4 / AI 写作 3 / 社区与话题 3 / 账号与隐私 3)+ 联系支持(反馈表单 + 邮箱 `support@weavery.example`)。旧文档误记为"占位,待完善"。

- 涉及:[[功能/账户与治理#帮助中心]]
- 状态:**文档已修正**(见帮助中心章节的真实 FAQ 结构)
- 建议:开发时按完整 FAQ 实现,勿当占位

## Q15

**owner 模式无后端校验**

帖子详情的作者专属操作(编辑/删除)通过 `/[?&]owner=1/.test(location.search)` 纯前端判断,无后端权限校验。

- 涉及:[[功能/帖子详情与Remix#作者专属操作]]
- 影响:任何人加 `?owner=1` 即可看到编辑/删除入口(前端可见),实际删除需后端兜底
- 建议:`owner=1` 仅作 UI 开关,真正的编辑/删除权限由后端按作者身份校验

## Q16

**注册密码未做长度校验**

注册表单密码字段标注 hint"至少 8 位",但前端只校验 `trim()` 非空,未做长度/复杂度校验。

- 涉及:[[功能/账户与治理#登录注册]]
- 影响:弱密码可注册
- 建议:前后端都做 ≥8 位校验(及复杂度策略)

## Q17

**第三方登录未实现**

auth 页 CSS 中定义了 `.social-row` / `.btn-social` 样式,但 HTML 未渲染任何第三方登录按钮,属预留入口。

- 涉及:[[功能/账户与治理#登录注册]]
- 影响:第三方登录能力缺失
- 建议:M1 明确是否上线第三方登录;不上线则移除 CSS 避免误解

## Q18

**搜索页 ⌘K 未绑定快捷键**

search.html 顶栏搜索框显示了 `⌘K` 提示徽标,但未绑定 ⌘K/Ctrl+K 快捷键(topic.html 才有该绑定)。

- 涉及:[[功能/话题与搜索#搜索]]
- 影响:用户按 ⌘K 无反应,与提示不符
- 建议:全站统一绑定 ⌘K(见 [[全局规范#全局快捷键]])

## Q19

**AI 作者徽章无视觉区分**

profile 页 CSS 定义了 `.author-role.ai`(黑底白字)样式,但 `apply()` 渲染 AI 作者时把徽章重置为普通 `profile-badge`,导致 AI 作者与认证作者徽章视觉完全相同。

- 涉及:[[功能/作者主页#资料头]]
- 影响:AI 作者在主页无法与人类认证作者区分
- 建议:AI 作者徽章采用独立的视觉样式(如 `.author-role.ai` 黑底白字)

## Q20

**看板切换时间范围 KPI / 环形图不更新**

dashboard 切换"近 7 / 30 / 90 天"时只重新渲染阅读趋势柱状图,四项 KPI 数字、AI 创作来源环形图、`panel-note`("last 7d")均不变;KPI 的环比 delta 也固定为"较上周"。

- 涉及:[[功能/创作者中心#创作者数据]]

- 建议:时间范围切换应联动 KPI / 环形图 / delta 文案
