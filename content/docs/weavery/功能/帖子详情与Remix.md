## AI 透明度卡片

AI 生成内容在文章顶部强制展示透明度卡片。位置:文章最顶部 `.art-meta`(在 `.art-title` 之前),`display: flex; gap: 8px; flex-wrap: wrap`,三元素横向排列:

| 序  | 元素         | 文案 / 说明                                                      |
| --- | ------------ | ---------------------------------------------------------------- |
| 1   | `.badge-ai`  | **"基于 AI 生成"**(描边胶囊,双星 icon)                           |
| 2   | `.model-tag` | **"GPT-4o"**                                                     |
| 3   | `.model-tag` | **"提示词 · v3"**(用"·"分隔的提示词版本号,与文档"提示词 vN"对应) |

**第二处 AI 标识**:`.art-byline` 内 `.byline-name`(如 "云小织") + `.author-role.ai` **"AI 作者"**(黑底白字)。

**byline-sub 三段式**(中点分隔):**"专栏名 · 时间 · 约 N 分钟阅读"**(如 "生成式设计观察 · 40 分钟前 · 约 3 分钟阅读")。

> [!important] 透明度是制度
> 这是 weavery 的核心文化要求,见 [[../术语表]] 的"基于 AI 生成"和社区准则第 2 条。

## 提示词与参数折叠块

文章正文中嵌入的"查看生成提示词与参数"折叠区,位置在 `.art-body` 正文流中,前面有 `<h2>提示词与参数</h2>`。

**折叠态**(`.prompt-card`):仅 `.prompt-head`(全宽 button)。结构:星星 icon(accent) + **"查看生成提示词与参数"** + 右侧 chev 下拉箭头;hover 浅灰底。

**展开态**(`.is-open`):chev rotate(180deg);`.prompt-body` `max-height` 过渡。展开后三段:

| 段         | class                                             | 说明                                                                                                                                    |
| ---------- | ------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| 提示词正文 | `.prompt-inner`(`pre` 标签)                       | mono 13px / line-height 1.75 / 背景 accent 3% 淡黑 / `white-space: pre-wrap`。完整提示词分 **5 段**:"角色:""任务:""场景:""要求:""输出:" |
| 参数       | `.prompt-params`(border-top 分隔,flex wrap gap 8) | **4 个 model-tag**:**"模型 GPT-4o"** / **"温度 0.8"** / **"长度 800"** / **"风格 极简中文"**                                            |
| 操作       | `.prompt-actions`                                 | 复制按钮(`.action-btn`,文案 **"复制"**)+ **"放入工作台"**(`.btn-remix` 黑底白字,链 `create.html`)                                       |

**复制交互**:`navigator.clipboard.writeText` 写入 prompt 文本,按钮文案 **"复制"→"已复制"**,**1600ms 后恢复**。

| 操作       | 行为                             |
| ---------- | -------------------------------- | ----------------------- |
| 复制       | 复制完整 prompt + 参数           |
| 放入工作台 | 带 prompt 跳 [[功能/AI写作工作台 | 工作台]] 起草(即 Remix) |

## 作者专属操作

通过 `?owner=1` 参数显示(仅文章作者可见):

| 操作 | 行为                                                           |
| ---- | -------------------------------------------------------------- |
| 编辑 | 跳工作台 `?edit=1` 编辑模式(见 [[功能/AI写作工作台#编辑模式]]) |
| 删除 | **二次确认**("确认删除?")后删除                                |

### 删除二次确认机制

1. 第一次点:`dataset.confirming = "1"`,按钮 innerHTML 替换为 **"确认删除?"**(保留垃圾桶 icon),强制 `borderColor/color = --danger`
2. **2500ms 超时**自动恢复"删除"原样
3. 超时内再点:toast **"文章已删除"** → **900ms 后 `location.href = "me.html"`**

> [!important] owner 模式无后端校验
> owner 模式是纯前端 URL 参数,无后端校验(见 [[待确认问题#Q15]]),真正的编辑 / 删除权限需后端按作者身份校验。

## Remix(改编 / 再创作)

> 基于他人作品(主要是其提示词)二次创作,weavery 的核心特色之一。

**入口**:

- 文章底部"放入工作台"
- 文章侧栏"开始改编 / 用 AI 改编这篇作品"

**Remix 流程**(详见 [[../用户流程#流程二|用户流程]]):

1. 点击"放入工作台 / 开始改编"
2. 跳工作台,带上原作品的提示词起稿
3. 改写成自己的版本后发布
4. 发布时可标注"基于 XX 的作品改编"
5. 原作者收到 **Remix 通知**(见 [[功能/社交互动#通知中心|通知中心]] 的 Remix 分类)

**关联数据**:

- 作者主页显示"被 Remix"次数(见 [[功能/作者主页|作者主页]])
- 通知中心有专门的 Remix 筛选分类

## 评论区与 @AI 助手

### composer(评论输入区)

`.composer`(relative):

| 区块            | 说明                                                                                                                                                                                                |
| --------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `.composer-box` | `:focus-within` 变 accent + focus-ring;内含 textarea(placeholder **"写下你的想法,@AI 助手 会被召唤…"**)                                                                                             |
| `.composer-bar` | `.chip-btn` **"@AI 助手"**(28px 高,黑边胶囊,点击直接追加 `"@AI 助手 "` 到输入框)+ `.composer-hint`(`ml: auto`) **"Enter 发送"** + `.btn.btn-primary.btn-send` **"发送"**(输入 trim 为空时 disabled) |
| `.mention-pop`  | 绝对定位 `bottom: calc(100% + 6px)`(浮在 composer 上方),240px 宽。5 候选:第 1 个 `.is-ai` **"AI 助手"**(星星 icon、accent、600),其后普通用户(陈默 / 林晚 / 苏航)                                    |

**触发逻辑**:正则 `/(^|\s)@([^\s@]*)$/` 匹配光标前文本;选中后把最后一个 `@` 后内容替换为 `@{name} `。

### @提及

评论输入框支持 `@提及`:

- 输入 `@` 弹出候选(AI 助手 / 文章作者 等)
- 可点击 `@AI 助手` chip 快速召唤

### 评论项结构

`.comment`(flex gap 14,border-top 分隔)= `avatar-sm` + `.comment-body`:

| 区块               | 说明                                                                     |
| ------------------ | ------------------------------------------------------------------------ |
| `.comment-head`    | name + 可选 `.comment-ai-tag` + time                                     |
| `.comment-text`    | 评论正文                                                                 |
| `.comment-ai-note` | (可选)AI 免责说明                                                        |
| `.comment-foot`    | `.c-like`(点赞数)+ `.c-reply` **"回复"**(点击填 `"@"+name+" "` 并 focus) |

**无排序 UI、无分页**。

### 评论互动

- 评论可回复(嵌套)

### @AI 助手 召唤

> 评论区独有能力,让 AI 参与讨论。

**完整文案链**(详见 [[../用户流程#流程三|用户流程]]):

1. 输入框 placeholder:**"写下你的想法,@AI 助手 会被召唤…"**
2. composer-bar 快捷按钮:`.chip-btn` **"@AI 助手"**(点击直接追加)
3. 评论 head 提示:**"@AI 助手 可召唤 AI 一起参与讨论"**
4. mention 弹窗候选首项:**"AI 助手"**(`is-ai` 高亮)
5. 发送触发:`sendComment()` 检测 `text.indexOf("@AI 助手") > -1`
6. **typing 占位**:AI 头像 + `.typing-dots`(3 个 5px 圆点,blink 1.2s 错相 0.18s / 0.36s)+ 文案 **"AI 助手 正在阅读上下文并生成回复…"**
7. **1400ms 后**:移除 typing,插入 AI 评论(示例回复:"刚读完上面几条评论…有什么想让我详细展开的,继续 @我。")
8. 新评论带 `.comment-ai-tag` **"AI 评论"** + `.comment-ai-note` 免责
9. **bumpCount**:`comment-count` 与 `comment-count-head` 同步 +1(26 → 27)
10. **通知联动**:作者收到 **"@AI 助手 评论了你的文章「…」"** 通知(带 AI 标签)

## 业务规则

1. **AI 内容必标**:有 AI 参与的文章必须显示透明度卡片
2. **提示词可复现**:折叠块提供完整 prompt + 参数
3. **Remix 可追溯**:改编可标注出处,原作者收到通知
4. **@AI 助手带免责**:AI 评论必须附免责说明
5. **删除二次确认**:作者删除文章需二次确认,防误操作
