# 事件系统

## 为什么需要 Event

三个客户端（macOS / iOS / Web）需要实时观察 Agent 状态。

如果没有 Event System：
- 客户端需要轮询服务端，效率低、延迟高
- 各客户端状态不一致
- 新增客户端需要重复实现状态查询逻辑

有了 Event System：
- 服务端主动推送状态变更
- 所有客户端保持最终一致
- 新增客户端只需订阅 Event

---

## 什么是 Event

Event 是系统状态变化的通知。它是一个不可变的事件记录，包含：
- 事件类型
- 关联的 Session ID
- 事件数据 payload
- 时间戳

---

## Event 生命周期

```
Agent Runtime
    ↓ 产生 Event
Event Bus
    ↓ 分发
Subscribers (Clients)
    ↓ 更新 UI
```

1. Agent Runtime 执行过程中产生 Event
2. Event 被发送到 Event Bus
3. Event Bus 分发给所有订阅的客户端
4. 客户端根据 Event 更新本地 UI

## V1 Event 列表

### Session 事件

| Event | 说明 | 用户可见 |
|--------|------|---------|
| `session.created` | Session 创建 | ✅ |
| `session.resumed` | Session Resume | ✅ |
| `session.completed` | Session 完成 | ✅ |
| `session.failed` | Session 失败 | ✅ |
| `session.stopped` | Session 被停止 | ✅ |

### Agent 事件

| Event | 说明 | 用户可见 |
|--------|------|---------|
| `agent.started` | Agent 启动 | ✅ |
| `agent.stopped` | Agent 停止 | ✅ |
| `agent.thinking` | Agent 正在思考 | ✅ |
| `agent.message` | Agent 生成消息 | ✅ |

| Event | 说明 | 用户可见 |

| `tool.started` | Tool 开始执行 | ✅ |

| Event | 说明 | 用户可见 |
|--------|------|---------|

## 事件格式

```json
{
  "id": "evt_001",
  "type": "tool.completed",
  "sessionId": "session_001",
  "payload": {
    "toolName": "write_file",
    "input": {
      "path": "src/auth.ts",
      "content": "..."
    },
    "output": "File written successfully",
    "duration": 1.2
  },
  "timestamp": "2025-01-15T10:30:00Z"
}
```

## Event 订阅

### 客户端订阅

| 客户端 | 订阅范围 | 说明 |
|--------|---------|------|
| macOS | 当前 Session 的所有 Event | 实时显示 Agent Activity |
| iOS | 当前查看的 Session 的 Event | 实时更新状态 |
| Web | 用户订阅的 Session 的 Event | 实时显示进度 |

### 订阅方式

- V1 使用 WebSocket 长连接
- 客户端连接时指定 Session ID
- 服务端推送该 Session 的所有 Event
- 连接断开时，客户端重新连接后获取历史 Event

---

## 事件去重

- 每个 Event 有唯一 ID
- 客户端忽略重复的 Event ID
- 断线重连时，客户端发送最后收到的 Event ID
- 服务端从该 ID 之后补发缺失的 Event

## 系统内部事件

以下事件仅供系统使用，不暴露给用户：

| Event | 说明 |
|--------|------|
| `system.heartbeat` | 心跳检测 |
| `system.connection.established` | WebSocket 连接建立 |
| `system.connection.closed` | WebSocket 连接关闭 |

## 与 Session 的关系

```text
Session
  ├── Messages（用户消息、Agent 消息）
  ├── ToolExecutions（Tool 调用记录）
  └── Events（状态变化通知）

Events 是 Session 的"实时视图"：
- ToolExecutions 是持久化的执行记录
- Events 是实时推送的状态通知
- 两者数据来源相同，但用途不同
```

---

## V1 Event 不做什么

- 不定义复杂的 Event Schema（简单 JSON 即可）
- 不做 Event 持久化（V1 只保留 Session 和 ToolExecution 的持久化数据）
- 不做 Event 过滤规则（客户端自己决定显示哪些）
- 不做 Event 回放功能（V1 只显示最新状态）
