## Story 1：用户在 Mac 上创建 Workspace

**角色**：独立开发者  
**设备**：macOS App

1. 用户打开 Elysia macOS App
2. 点击「新建 Workspace」
3. 选择本地代码库文件夹
4. 系统自动检测语言和项目类型
5. Workspace 创建完成，进入 Workspace 首页

**关键页面**：Workspace 列表 → 新建 Workspace → 选择文件夹

---

## Story 2：用户创建 Coding Session

**角色**：独立开发者  
**设备**：macOS App

1. 用户在 Workspace 首页点击「新建 Session」
2. 输入任务描述（如"修复测试失败"）
3. Session 创建，Agent 自动启动
4. 界面切换至 Session 详情页
5. Agent 开始执行任务

**关键页面**：Workspace 首页 → 新建 Session → Session 详情

---

## Story 3：用户告诉 Agent 修复测试失败

**角色**：独立开发者  
**设备**：macOS App

1. 用户在 Session 中输入："这个项目里有测试失败，帮我修复"
2. Agent 收到消息，开始执行
3. Agent 调用 `search_code` 查找测试文件
4. Agent 调用 `list_files` 浏览项目结构
5. Agent 调用 `read_file` 读取测试文件
6. Agent 调用 `run_command` 运行测试
7. Agent 观察到测试失败结果
8. Agent 分析失败原因，调用 `read_file` 读取相关代码
9. Agent 调用 `write_file` 修复代码
10. Agent 再次调用 `run_command` 运行测试
11. Agent 验证测试通过
12. Agent 汇报任务完成

**关键交互**：用户输入 → Agent 自动执行 → 实时反馈 → 用户确认完成

---

## Story 4：Agent 完整执行流程

```text
User: "修复测试失败"
  ↓
Agent: Understanding
  ↓ "让我先看看项目结构和测试文件"
Agent: search_code "test" + list_files
  ↓
Agent: read_file 测试文件
  ↓
Agent: run_command "npm test"
  ↓ "测试失败了，我来分析原因"
Agent: read_file 相关源码
  ↓
Agent: write_file 修复代码
  ↓
Agent: run_command "npm test"
  ↓ "测试全部通过，任务完成"
Agent: Completed
```

**Agent Loop**：Understand → Plan → Act → Observe → Verify → Complete

## Story 5：用户在 iPhone 上查看 Agent 工作状态

**角色**：独立开发者  
**设备**：iOS App

1. 用户离开 Mac，拿出 iPhone
2. 打开 Elysia iOS App
3. 点击「设备」→ 选择 MacBook
4. 看到当前活跃的 Session
5. 实时查看 Agent Activity：
   - Agent 正在思考
   - Tool 调用列表
   - 最新 Diff
   - Terminal Output
6. 用户看到 Agent 正在修复代码，等待完成

**关键页面**：Devices → Session List → Session Detail → Activity

---

## Story 6：用户从 iPhone 向 Agent 发送新指令

**角色**：独立开发者  
**设备**：iOS App → macOS

1. 用户在 iPhone 上查看 Session，发现 Agent 修复的方向不对
2. 用户在 Session 中输入："不要修改那个文件，换个思路"
3. 消息通过 Event System 实时发送到 macOS 上的 Agent
4. Agent 收到新消息，调整执行方向
5. 用户继续在 iPhone 上观察进度

**关键交互**：iOS 输入 → Event 发送 → Agent 接收 → 继续执行 → iOS 实时更新

---

## Story 7：用户通过 Web 查看同一个 Session

**角色**：独立开发者  
**设备**：Web UI

1. 用户在办公室，Mac 在家里
2. 打开浏览器，访问 Elysia Web
3. 登录（V1 通过设备绑定或简单 token）
4. 看到 Session 列表，包括 Mac 上正在运行的 Session
5. 实时查看 Agent Activity
6. 用户看到 Agent 卡住了，通过 Web 发送"停止"
7. Agent 停止执行

**关键页面**：Workspace → Session List → Session Detail

---

## Story 8：Agent 完成任务

**角色**：系统  
**场景**：Agent 完成所有验证

1. Agent 运行测试，所有测试通过
2. Agent 检查代码变更，确认符合用户要求
3. Agent 将 status 标记为 completed
4. 系统发出 `task.completed` Event
5. 所有客户端（macOS / iOS / Web）收到通知
6. UI 更新为"任务完成"
7. Agent 生成总结：
   - 修改了哪些文件
   - 运行了哪些命令
   - 测试结果如何
8. Session 状态变为 completed，可 Archive

## Agent Loop 详细流程

```text
┌─────────────────────────────────────────┐
│              Start Task                  │
└─────────────────────────────────────────┘
                    ↓
┌─────────────────────────────────────────┐
│  Understand                              │
│  - 分析用户输入                           │
│  - 识别任务类型                           │
│  - 确定需要操作的文件/目录                 │
└─────────────────────────────────────────┘
                    ↓
┌─────────────────────────────────────────┐
│  Plan                                    │
│  - 制定执行计划                           │
│  - 确定调用哪些 Tool                      │
│  - 确定调用顺序                           │
└─────────────────────────────────────────┘
                    ↓
┌─────────────────────────────────────────┐
│  Act                                     │
│  - 调用 Tool（read_file / search_code 等） │
│  - 发送 tool.started Event               │
└─────────────────────────────────────────┘
                    ↓
┌─────────────────────────────────────────┐
│  Observe                                 │
│  - 接收 Tool Result                       │
│  - 分析结果                               │
│  - 发送 tool.completed / tool.failed Event │
└─────────────────────────────────────────┘
                    ↓
                    ├─── 失败 ───▶ Retry（最多 N 次）
                    │                    ↓
                    │              ┌──────────────┐
                    │              │ 失败 N 次后  │
                    │              │ 请求用户介入  │
                    │              └──────────────┘
                    ↓
┌─────────────────────────────────────────┐
│  Verify                                  │
│  - 运行测试验证结果                        │
│  - 检查代码变更是否符合预期                  │
│  - 确认任务完成标准是否达成                  │
└─────────────────────────────────────────┘
                    ↓
            ┌───────┴───────┐
            ▼               ▼
      ┌─────────┐     ┌─────────┐
      │ Complete │     │ Continue│
      │ Task     │     │ (追加)  │
      └─────────┘     └────┬────┘
                             ↓
                      ┌─────────┐
                      │  Back   │
                      │ to Act  │
                      └─────────┘
```

## 用户介入点

| 时机 | 用户操作 | Agent 行为 |
|------|---------|-----------|
| Tool 执行前 | 查看 Agent 计划 | 显示即将执行的 Tool 列表 |
| Tool 执行中 | 实时查看进度 | 持续发送 Event |
| Tool 执行失败 | 查看错误信息 | 自动 Retry 或请求用户决策 |
| 任务完成前 | 查看最终结果 | 等待用户确认 |
| 用户主动停止 | Stop Agent | 立即停止当前 Tool，保留状态 |
| 用户追加消息 | 发送新消息 | 根据新消息调整执行方向 |

## 失败处理

### Tool 执行失败

1. Agent 收到 error 结果
2. Agent 分析错误原因
3. Agent 自动 Retry（最多 3 次）
4. 如果 Retry 失败：
   - Agent 向用户报告错误
   - Agent 提供可选方案
   - 等待用户决策

### 测试失败

1. Agent 运行测试，发现失败
2. Agent 分析测试输出
3. Agent 定位失败原因
4. Agent 修复代码
5. Agent 重新运行测试
6. 如果仍然失败：
   - Agent 报告当前状态
   - 等待用户决策（继续修复 / 人工介入）

### Agent 卡住

1. 用户发现 Agent 长时间无响应
2. 用户点击「停止」
3. Agent 立即停止
4. Session 状态变为 stopped
5. 用户可以 Resume 或重新开始
