# 话题与搜索

发现内容的两个入口:**话题页**(按主题聚合)和**搜索**(全局检索)。

## 话题页 `topic`

> 按主题聚合内容的专题页,类似社区版块。

### 页面结构

| 区块   | 内容                                              |
| ------ | ------------------------------------------------- | --------- |
| 话题头 | `#话题名`、描述、讨论数 / 关注人数 / 编辑推荐次数 |
| 操作   | 关注话题 + 发帖(跳 [[产品/功能/AI写作工作台       | 工作台]]) |
| 排序   | 最新 / 热门 / 讨论最多                            |
| 侧栏   | 相关话题 + **话题规则**                           |

### 话题头

`.topic-hero`(flex row,gap 24px,padding 40px 0 28px,有 rise-in 入场动画):

- 左 `.topic-hero-main`:
  - `.topic-kicker`:`.topic-hash`(**mono 26px 700 muted**)+ `.topic-name`/h1(display 32px 800 letter-spacing -0.02em),baseline 对齐
  - `.topic-desc`:16px muted,max-width 54em,line-height 1.7
  - `.topic-meta`:**三项用 `.sep`(1px×12px 竖线)分隔**,顺序固定:**"12.4k 讨论"** → **"38k 人关注"** → **"编辑推荐 · 5 次"**
- 右 `.topic-hero-actions`:关注话题按钮 + 发帖按钮
- **无 banner、无头图**(纯白底文字头部);移动端改 column,actions 撑满

### 话题卡片

话题下的内容列表**复用 feed 同款 `.card`**(非 search 的 res-row),`.feed-list` flex column gap 20px。卡片字段与 [[产品/功能/信息流#三种卡片|信息流卡片]] 一致。

### 排序逻辑

三选一:最新 / 热门 / 讨论最多。实现:`latest`=原始顺序;`hot`=按 likes 降序;`discuss`=按 views 降序。排序前**统一把 `k` 还原为数值再比较**(如 `9.6k` → 9600),避免字符串比较失真(见 [[待确认问题#Q8]])。

### 相关话题

- 侧栏第一个 panel,title"相关话题",容器 `#related-list`
- 每个 `.topic`:横向布局,`.topic-rank`(**"01"–"04"** 带前导 0,18px 宽,mono tabular-nums,muted)+ `.topic-name`(14px 600)
- **只显示序号和名字,不显示讨论数/描述**
- 每个话题**固定 4 个 related**(硬编码,非动态计算)

### 话题规则(特色)

每个话题有**专属规则**,约束该话题下的发布行为。完整规则表(逐字):

| 话题                  | 规则原文                                                                                |
| --------------------- | --------------------------------------------------------------------------------------- |
| 独立开发者            | "欢迎分享真实收入、成本与工具链拆解。广告与付费推广请移步相关渠道。"                    |
| 设计系统              | "分享请附组件示例或版本说明。讨论设计决策时,建议说明上下文与取舍。"                     |
| 开源与商业化          | "涉及具体项目可附链接与数据,但禁止在讨论中硬广或拉新。"                                 |

| 提示词                | "发布提示词请附示例输入与输出。鼓励注明模型版本与温度等参数,便于他人复现。"             |

> [!important] 分版治理
> 话题规则在右侧栏 panel(非折叠),直接展示。实现了**分版块治理**——不同话题有不同内容要求,比全局社区准则更细粒度。

### 关注态与发帖

- 关注按钮 `#tp-follow`:初始由数据 `topic.followed` 决定。**只有"提示词"和"AI 写作"默认 followed: true**,其余 false
  - 未关注:文案 **"关注话题"**,accent 黑字 + border + 白底;hover 黑底白字
  - 已关注(`.is-followed`):文案 **"已关注"**,muted 灰字灰底;hover 变深灰
- 发帖按钮:文案 **"发帖"**(+ 图标),点击跳 `create.html?t={话题}`,工作台识别 `?t=` 参数并预填该话题标签(见 [[待确认问题#Q7]])

### 发帖入口

话题页"发帖"按钮跳工作台,并预填该话题标签。

## 搜索 `search`

> 全局搜索 + 无关键词时的探索发现页。

### 探索态(无关键词)

无搜索词时显示发现页:

**hero-search 区**(max-width 560px 居中):

- h1:**"搜索 织云 社区"**(注意空格)
- p 副标题:**"文章、作者,还有 AI 生成的提示词、模型对比与话题"**
- 热门 label:**"热门:"** + 5 个 `.hot-chip`(button,data-hot):**配色、提示词、模型对比、翻译腔、AI 编程**;点击直接 showResults

| 区块           | 内容                                           |
| -------------- | ---------------------------------------------- |
| 大搜索框       | 输入关键词                                     |
| 热门搜索 chips | 如 配色 / 提示词 / 模型对比 / 翻译腔 / AI 编程 |
| 热门话题卡片   | 网格展示热门话题                               |
| 推荐作者       |                                                |

**热门话题区**(section-title"热门话题",`.topic-grid` 3 列,≤900px 2 列,≤760px 单列):**固定 6 张卡片**,字段:`.tc-head`(.tc-hash # + .tc-name + .tc-count 右对齐 tabular-nums)+ .tc-desc + .tc-tags(2 个 .tag)。六卡:提示词 8.9k / 模型对比 6.2k / 梗图 4.1k / 工作流 3.5k / AI 写作 7.4k / AI 编程 12.4k。

**推荐作者区**(section-title"推荐作者",3 列):固定 3 张——云小织(avatar-g3"云",2.4k 关注,AI 作者标)/陈默(12.8k)/林晚(8.3k),各含 follow-btn(关注↔已关注)。

### 结果态

输入关键词后,结果按 Tab 分类:

| Tab  | 内容       |
| ---- | ---------- |
| 全部 | 所有匹配   |
| 文章 | 匹配的文章 |
| 作者 | 匹配的作者 |
| 话题 | 匹配的话题 |

结果项包含:AI 标识、模型标签、阅读数等。

支持 URL `?q=` 直接进入结果态(便于分享/外链)。

- results-head:h1 **"「`<span class="q">关键词</span>`」"**(全角引号,q 用 mono + accent)+ `<span class="count">N 个结果</span>`;max-width 720px
- Tab `.res-tabs`(全部/文章/作者/话题,active 用 box-shadow inset 0 -2px accent 下划线)

每类结果项字段:

| 类型            | 字段                                                                                   |
| --------------- | -------------------------------------------------------------------------------------- |
| 文章 `.res-row` | badge-ai"AI 生成" + model-tag + res-title + res-sub(**"作者 · 角色 · 时间 · N 阅读"**) |
| 作者            | avatar-sm + res-title(名 + 可选 AI 作者标)+ res-sub(**"简介 · N 关注 · N 篇作品"**)    |
| 话题            | res-title **"# 话题名"**(# 用 mono muted)+ res-sub(**"N 讨论 · 标签1 / 标签2"**)       |

**"全部"Tab 特殊**:不分混合列表,分 3 子块(文章 3 条/作者 2 条/话题 2 条),每块前 `.res-block-title`。

### 交互缺失

> [!warning] 交互缺失
> 搜索框**无历史记录、无联想建议、无清除按钮**(`autocomplete="off"`)。空值提交只聚焦不报错。**无筛选、无排序**,唯一切换是类型 Tab。search 页显示了 ⌘K 提示但未绑定(见 [[待确认问题#Q18]])。开发时需确认是否补齐。

### 顶栏搜索 vs 探索页大框

- 顶栏 `.search`:GET 跳转(action="search.html",input name="q"),由 URL 驱动
- 探索页 `#hero-form`:无 action,JS preventDefault,**纯客户端渲染**(隐藏 explore/显示 results)
- 两者 placeholder 略不同:顶栏"搜索文章、话题或作者"(无尾点),大框"搜索文章、话题或作者…"(有省略号)

### 移动端

<1020px 整个侧栏 `.sidebar { display: none }`,但**关键侧栏内容(话题规则、热门话题)降级到正文下方可展开抽屉**,避免在窄屏完全消失(见 [[待确认问题#Q10]])。

### 空结果

无匹配时提示:"没有找到相关内容,换个关键词试试,或去工作台让 AI 写一篇。"

> [!tip] 引导创作
> 搜索无结果的引导文案直接指向工作台,体现了 weavery "找不到就自己写一篇"的创作社区定位。

## 业务规则

1. **话题有规则**:每个话题可设独立规则,约束发布
2. **话题排序三选一**:最新 / 热门 / 讨论最多
3. **搜索结果分类**:支持按 文章/作者/话题 过滤
4. **搜索可外链**:`?q=` 支持分享搜索结果
