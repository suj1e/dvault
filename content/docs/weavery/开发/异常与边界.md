# 异常与边界场景

> 现有文档写的全是"正常路径",本篇补全"正常路径之外"的部分——AI 失败、断网、并发冲突、输入超限、账户边界、数据完整性。每条统一给"触发条件 + 处理策略 + 用户可见反馈",开发可直接据此实现。

## 统一格式说明

每个场景用四级标题 `#### 场景名`,下设三段固定结构:

- **触发条件**:什么情况下会发生
- **处理策略**:系统怎么做(重试 / 降级 / 队列 / 兜底)
- **用户可见反馈**:用户看到什么(Toast / 占位 / 状态变化)

部分场景额外加 **数据影响**:对持久化数据(文章、评论、关注、用量记录等)的影响。

> [!important] 优先级
> A 类(AI 相关异常)是 weavery 的核心,必须最先实现且体验最克制;其余按所属模块的迭代节奏推进。Toast 时长统一遵循 [[全局规范#Toast 规范]](默认 2000ms,拦截类 2600ms)。

## A. AI 相关异常

AI 是 weavery 的产品核心,这类异常要"克制、可恢复、不污染正文",尤其注意:**AI 任何失败都不应直接改写用户的文档**。

#### A1. AI 调用超时

- **触发条件**:工作台 `/润色`、`/续写` 等指令发出后超过阈值(建议 **30s**)仍无响应。
- **处理策略**:超时即取消请求(abort);对话日志中保留用户这条指令(`zd-console-log`,见 [[全局规范#数据契约(localStorage 键全集)]]);不写入文档正文;提供"重试"入口。
- **用户可见反馈**:AI 气泡显示"AI 响应超时,点此重试"(替换 `.log-pending` 无限转圈);重试复用原指令;输入框保持可用。
- 见 [[产品/功能/AI写作工作台#状态机]](`busy` 全局标志)。

#### A2. AI 调用失败(模型错误 / 限流 429)

- **触发条件**:模型返回错误(5xx),或触发限流(429)。
- **处理策略**:区分错误类型——
  - **限流(429)**:提示"稍后再试",或自动切换备用模型(见 [[产品/功能/AI写作工作台#写作配置]] 的可切换模型);
  - **模型错误(5xx)**:提示重试,不切换模型。
- **用户可见反馈**:Toast **"AI 暂时无法响应,请稍后重试"**;在 `AiUsage` 记录一次失败调用(含 model / error / 时间),用于 dashboard 用量统计口径一致。
- 数据影响:失败调用计入 AiUsage,但**不计入"成功创作"配额**。

> [!warning] 429 与配额的区分
> 429 可能来自"全局限流"也可能来自"个人配额超限",两者反馈不同(见 [[#A5. AI 用量超限]])。后端需返回可区分的错误码,前端据此走不同分支。

#### A3. @AI 助手召唤失败

- **触发条件**:评论带 `summon_ai=true`(`sendComment()` 检测到 `@AI 助手`),但 AI 生成失败。
- **处理策略**:typing 动画(1400ms)结束后**不插入空评论**;改为插入一条系统提示评论;不向作者推送"@AI 助手 评论了你的文章"通知(正常路径会推送,见 [[产品/功能/帖子详情与Remix#@AI 助手召唤]])。
- **用户可见反馈**:评论区显示一条灰底系统提示 **"AI 助手暂时无法响应,请稍后再试"**(替代正常 AI 评论卡);作者无通知。
- 数据影响:不产生 AI 评论记录;AiUsage 记一次失败。

#### A4. AI 评价生成失败

- **触发条件**:作者主页 `GET /ai/review` 失败(正常路径为 `900 + random*600ms` 加载 + 16ms/字打字机,见 [[产品/功能/作者主页#AI 评价(特色功能)]])。
- **处理策略**:评分列显示占位 **"—"**;三维条不填充;评语区显示"评价生成失败"。
- **用户可见反馈**:**"重新生成"按钮保持可用**(`.ai-regen`,非 `is-busy` 态),点击重试;免责声明仍显示。
- 数据影响:无;评价本就"仅供娱乐参考",不参与权重。

#### A5. AI 用量超限

- **触发条件**:创作者中心 dashboard 的"AI 创作用量"达到配额上限(原型未体现代额 UI)。
- **处理策略**:工作台 AI 调用后端返回 429 并带 `reason=quota_exceeded`;前端区分于 [[#A2. AI 调用失败(模型错误 / 限流 429)]] 的全局限流;提示升级或明日重置。
- **用户可见反馈**:工作台 Toast **"今日 AI 用量已达上限"**;dashboard 显示配额进度条。
- 配额机制已决:**M1 不设上限**(全部免费),先跑通体验;后续版本再加配额(额度、重置周期、是否区分模型)。见 [[待确认问题#Q27]]。

> [!note] M1 策略
> M1 阶段 AI 用量**全部免费、不设上限**,优先让用户跑通"AI 辅助创作"的核心体验。dashboard 配额进度 UI 暂不强制,后续版本引入配额时再补。

#### A6. AI 生成内容被审核拦截

- **触发条件**:AI 输出含违规内容,被审核系统拦截。
- **处理策略**:阻止"应用"(正常路径下"应用"不可逆,见 [[产品/功能/AI写作工作台#状态机]] 的 `applied` 态);AI 气泡标记"内容未通过审核";保留对话日志供用户查看。
- **用户可见反馈**:**"应用"按钮禁用**;Toast **"该内容未通过审核,无法应用"**;用户可重发指令。
- 数据影响:不写入文档;AiUsage 可标记 `moderation=blocked`。

## B. 网络与离线

#### B1. 断网时自动保存(工作台)

- **触发条件**:编辑中断网(工作台自动保存依赖 localStorage,见 [[产品/功能/AI写作工作台#自动保存]])。
- **处理策略**:localStorage 兜底(已有机制,键 `zd-draft-title` / `zd-draft-content`);联网后自动同步到服务端。
- **用户可见反馈**:保存态由"正在保存…"→ 显示 **"离线已存本地"**;联网成功后变 **"已同步 HH:MM"**。

#### B2. 断网时发布

- **触发条件**:点"发布"时断网(正常路径 1200ms 完成,见 [[产品/功能/AI写作工作台#发布]])。
- **处理策略**:进入发布队列;联网后自动重试;期间按钮锁定,防止重复提交。
- **用户可见反馈**:按钮显示 **"发布中…"**(沿用 `busy` 标志);联网成功后变 **"已发布"**(`.is-done` 绿色态)。
- 数据影响:未确认发布前,文章仍以草稿形态存在,不产生 Post 记录。

#### B3. 断网时点赞 / 评论(乐观更新回滚)

- **触发条件**:点赞 / 评论请求发送失败。
- **处理策略**:点赞乐观更新(立即 +1,见 [[产品/功能/信息流#卡片互动]])→ 失败回滚(-1);评论失败则移除该评论 DOM。
- **用户可见反馈**:Toast **"操作失败,请重试"**;点赞数字回滚;评论消失。
- 数据影响:回滚后 Like / Comment 记录不落库。

> [!tip] 乐观更新的边界
> 只对"幂等、可回滚、低冲突"的操作用乐观更新(点赞、收藏、关注);评论这类有副作用且需审核的,失败即移除,不要"留一条 pending"。

#### B4. 弱网加载信息流

- **触发条件**:feed 请求慢或首次加载超时(原型为静态无分页,见 [[产品/功能/信息流#无分页]])。
- **处理策略**:骨架屏(skeleton)占位;超时(**10s**)自动重试一次;仍失败显示错误态。
- **用户可见反馈**:卡片骨架屏;失败显示 **"加载失败,点击重试"**。

## C. 并发与冲突

#### C1. 两人同时 Remix 同一篇

- **触发条件**:多用户对同一 Post 几乎同时发起 Remix。
- **处理策略**:都允许;各自生成**独立的新 Post**(带各自的 `source_post_id`,见 [[数据模型]]);互不阻塞。
- **用户可见反馈**:改编者各自看到自己的工作台;原作者收到**多条 Remix 通知**(见 [[产品/功能/帖子详情与Remix#Remix(改编 / 再创作)]])。
- 数据影响:产生多个新 Post,均指向同一 `source_post_id`;被 Remix 次数 +N。

#### C2. 作者多端同时编辑

- **触发条件**:作者在两台设备编辑同一篇文章(如桌面 + 手机)。
- **处理策略**:**采用乐观锁**——Post 增加 `version` 字段(默认 1,每次保存 +1);后提交者收到 `409 Conflict`;不覆盖;提示刷新后基于最新版本重试。
- **用户可见反馈**:Toast **"文章已被另一处修改,请刷新后重试"**(拦截类 2600ms);不静默覆盖。
- 并发策略已决:**乐观锁**(Post.version 字段),见 [[待确认问题#Q29]]。

> [!important] 不可用"后写覆盖"
> 编辑模式"保存即覆盖"(见 [[产品/功能/AI写作工作台#业务规则]]),多端场景下必须加版本控制,否则一端的内容会被无提示抹掉。

#### C3. 同时删除与评论

- **触发条件**:作者删除文章时,有人正在发送评论。
- **处理策略**:删除后,该文章的所有评论级联处理(隐藏或标记,策略见 [[#E2. 注销到期永久删除]] 的级联讨论);正在发送的评论请求失败。
- **用户可见反馈**:评论者 Toast **"文章已删除,评论失败"**;post 页对该评论者显示"文章已删除"或跳走。

#### C4. 关注 / 取关快速连点

- **触发条件**:用户快速多次点关注按钮(正常路径见 [[产品/功能/社交互动]])。
- **处理策略**:前端防抖(如 **300ms**);以最后一次操作为准,只发一个请求。
- **用户可见反馈**:按钮状态跟随最终结果(关注 / 已关注);中间态不闪烁。
- 数据影响:只产生一条 Follow / Unfollow 记录。

## D. 输入与限制

#### D1. 文章字数上限

- **触发条件**:正文超过字数上限 **5 万字**。
- **处理策略**:超限**阻止继续输入**(前端拦截,后端兜底),不让超出部分进入正文。
- **用户可见反馈**:字数计数变红(`--danger`);Toast **"文章字数不能超过 5 万字"**(拦截类 2600ms)。
- 上限值已决:**5 万字**(见 [[待确认问题#Q21]])。

#### D2. 标题 / 昵称长度

| 字段     | 上限           | 状态 |
| -------- | -------------- | ---- |
| 昵称     | `maxlength=20` | 已决 |
| 文章标题 | **100 字**     | 已决 |
| 评论     | **2000 字**    | 已决 |
| 私信     | **5000 字**    | 已决 |

- **处理策略**:达到上限时阻止继续输入;前端校验 + 后端兜底。
- **用户可见反馈**:输入框边框变红 / Toast 提示。
- 各字段上限已决,见 [[待确认问题#Q22]]。

#### D3. 图片上传限制

- **触发条件**:上传超大文件(>5MB),或非图片格式。
- **处理策略**:前端校验 `size`(**≤5MB**)+ `MIME`(**`image/*`**),并**自动压缩到 1920px 宽**;超限直接拒绝,不发请求。
- **用户可见反馈**:Toast **"图片不能超过 5MB"** 或 **"仅支持图片格式"**(拦截类 2600ms)。
- 限制已决:**≤5MB / `image/*` / 自动压缩到 1920px 宽**,见 [[待确认问题#Q23]]。

#### D4. 话题无内容

- **触发条件**:进入 `posts` 为空的话题(`职业成长 / 生活 / 翻译 / 写作 / 生成式设计`,见 [[待确认问题#Q9]])。
- **处理策略**:渲染空状态,不渲染空白列表。
- **用户可见反馈**:空状态——图标 + **"这个话题还没有内容,去工作台写第一篇"** + CTA 跳 `create.html?t={话题}`。

## E. 账户边界

#### E1. 注销冷静期

- **触发条件**:用户在危险区点"注销账号"(见 [[产品/功能/账户与治理#危险区]])。
- **处理策略**:进入 **30 天冷静期**;数据保留;期间可登录恢复。
- **用户可见反馈**:Toast **"注销流程(原型占位):30 天冷静期后生效"**(沿用原型文案)。
- 数据影响:账号标记 `pending_deletion + 到期时间`;内容暂不删。

#### E2. 注销到期永久删除

- **触发条件**:冷静期结束,用户未恢复。
- **处理策略**:**匿名化保留**——账号删除,但文章 / 评论保留可见,作者署名统一显示为"**已注销用户**",以维持他人评论与讨论的上下文连贯;个人信息(邮箱、密码、token、私信、关注关系、隐私设置等)清除。
- **用户可见反馈**:无(账号已不存在);关注该用户的人看到"已注销"(见 [[#F2. 被关注者注销]])。
- 级联策略已决:**匿名化保留**(文章 / 评论保留可见,署名改"已注销用户"),见 [[待确认问题#Q24]]。

> [!warning] 匿名化保留的理由
> 全删会破坏已有讨论的上下文(评论引用的原文消失);匿名化保留既维护了内容生态的连贯性,又通过清除个人信息划清隐私边界。Remix 源帖(F1)显示"基于匿名作者的作品改编",关注关系(F2)按此策略处理。

#### E3. 被封禁用户的可见性

- **触发条件**:账号被封禁(guidelines 执行分级"重"档,见 [[产品/功能/账户与治理#分级处理(三档)]])。
- **处理策略**:封禁用户**无法登录 / 无法发布**;其历史内容对他人**隐藏(非删除)**——内容仍存在于库中,但不向他人展示。
- **用户可见反馈**:被封禁者登录见"账号已被封禁";他人访问其 profile 或文章详情时,内容不可见。
- 可见性策略已决:**隐藏内容**(被封禁用户的已发布内容对他人不可见),见 [[待确认问题#Q25]]。

#### E4. 被限制功能用户

- **触发条件**:违规被限制功能(guidelines 第 7 条"重复或严重违规",中档处理)。
- **处理策略**:可浏览;**限制范围由管理员定制**——执行限制时,管理员可勾选具体限制哪些功能(发布 / 评论 / 点赞 / 收藏 / 关注 / AI 调用等),灵活组合,不一刀切。
- **用户可见反馈**:受限操作被拦截;Toast 提示"你的账号已被限制该功能"(拦截类 2600ms)。
- 限制范围已决:**管理员可定制**(勾选限制哪些功能),见 [[待确认问题#Q26]]。

## F. 数据完整性

#### F1. Remix 的原帖被删

- **触发条件**:被 Remix 的源文章(`source_post_id` 指向的 Post)被原作者删除。
- **处理策略**:**改编 Post 保留**;`source_post_id` 指向的原文渲染为"原作品已删除"占位。
- **用户可见反馈**:改编文章的"基于《xxx》改编"处显示 **"基于已删除的作品改编"**;阅读不受影响。
- 数据影响:改编 Post 的 `source_post_id` 保留(软引用),不级联删除改编作。

> [!note] 与注销级联的联动
> 若原文因作者注销(E2)而被匿名化保留,则此处显示"基于匿名作者的作品改编";若全删,则显示"基于已删除的作品改编"。两处策略需对齐。

#### F2. 被关注者注销

- **触发条件**:关注的人注销账号。
- **处理策略**:关注关系清理(follower 指向"已注销"占位账号);profile 显示"已注销"。
- **用户可见反馈**:关注列表中该用户标记 **"已注销"**;头像变默认;不可点入。
- 数据影响:Follow 关系按 E2 级联策略处理(全删则关系消失;匿名化则指向占位账号)。

#### F3. AI 模型下线

- **触发条件**:历史文章生成时用的 `model`(如某退役模型)已下线。
- **处理策略**:`model-tag`(见 [[全局规范#徽章系统]])**保留原值,暂不标注退役**;阅读体验不受影响。后续若有模型实际下线,再补退役标注。
- **用户可见反馈**:模型标签仍显示原名,无额外标注。
- 标注策略已决:**保留原值,暂不标注退役**(后续若有模型下线再加标注),见 [[待确认问题#Q28]]。

- **Q21 文章字数上限**——已决:**5 万字**,超限阻止输入(不区分免费 / 付费用户)。
- **Q22 文章标题 / 评论 / 私信长度上限**——已决:文章标题 **100 字** / 评论 **2000 字** / 私信 **5000 字**;前端校验 + 后端兜底。
- **Q23 图片上传大小 / 格式限制**——已决:单图 **≤5MB**、格式 `image/*`、**自动压缩到 1920px 宽**。
- **Q24 注销级联策略**——已决:**匿名化保留**;文章 / 评论保留可见,署名改"已注销用户";个人信息清除。Remix 源帖(F1)显示"基于匿名作者的作品改编",关注关系(F2)按此策略处理。
- **Q25 被封禁用户内容可见性**——已决:**隐藏内容**(对他人不可见,非删除);被封禁者本人登录见封禁提示。
- **Q26 被限制功能用户的限制范围**——已决:**管理员可定制**,执行限制时勾选限制哪些功能(发布 / 评论 / 点赞 / 收藏 / 关注 / AI 调用等),灵活组合。
- **Q27 AI 用量配额机制**——已决:**M1 不设上限**(全部免费),先跑通体验;后续版本再定额度、重置周期、是否区分模型、是否对游客关闭。
- **Q28 AI 模型下线的标注策略**——已决:**保留原值,暂不标注退役**;后续若有模型实际下线,再补"已退役"标注并维护退役模型清单。
- **Q29 多端编辑并发**——已决:**乐观锁**(Post.version 字段,默认 1,每次保存 +1,并发冲突时后提交者收 409);提示刷新后重试,不覆盖。
