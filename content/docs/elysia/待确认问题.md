# 待确认问题

以下问题需要在产品设计阶段或工程启动前确认。

---

## 产品层面

### Q1：模型选择策略

**问题**：V1 提供哪些模型选项？用户是否可以切换模型？

**选项**：
- A：固定使用一个模型（如 Claude Sonnet）
- B：提供 2-3 个预设模型选项
- C：允许用户配置任意模型

**建议**：B。提供 2-3 个预设选项，平衡灵活性和简单性。

---

### Q2：Session 存储位置

**问题**：Session 历史存储在本地还是云端？

**选项**：
- A：纯本地存储
- B：云端索引 + 本地执行
- C：完全云端

**建议**：B。云端索引用于多端发现 Session，但执行数据在本地。

---

### Q3：iOS 发现 macOS 的方式

**问题**：iOS 如何发现同一用户的 macOS 设备？

**选项**：
- A：同一 WiFi 自动发现（Bonjour）
- B：手动输入 IP / 配对码
- C：通过云端账号绑定

**建议**：B 或 C。V1 不要求账户系统，建议使用配对码方式。

---

### Q4：Web 端 Session 来源

**问题**：Web 端的 Session 从哪里来？

**选项**：
- A：Web 端独立创建，通过云端同步到 macOS
- B：只能查看 macOS 上创建的 Session
- C：两者都支持

**建议**：C。Web 可以独立创建，也可以查看 macOS 的 Session。

---

## 工程层面

### Q5：Agent Runtime 实现

**问题**：Agent Runtime 运行在哪里？

**选项**：
- A：macOS App 内嵌
- B：独立服务进程
- C：云端服务

**建议**：A。V1 中 Agent Runtime 嵌入 macOS App，直接访问本地文件系统。

---

### Q6：Event 传输协议

**问题**：Event 通过什么协议传输？

**选项**：
- A：WebSocket
- B：SSE（Server-Sent Events）
- C：WebRTC

**建议**：A。WebSocket 是最成熟的双向通信方案。

---

### Q7：多端通信架构

**问题**：macOS 如何与 iOS / Web 通信？

**选项**：
- A：macOS 作为服务端，iOS / Web 直连
- B：通过云端中转
- C：P2P 直连

**建议**：B。通过云端中转更稳定，不依赖内网穿透。

---

### Q8：代码库索引

**问题**：V1 是否需要代码库索引？

**选项**：
- A：需要，建立向量索引支持语义搜索
- B：不需要，使用文本搜索即可
- C：按需建立（用户首次使用时）

**建议**：B。V1 只用 `search_code` 做文本搜索，不做 RAG。

---

## 体验层面

### Q9：Agent 执行可见性

**问题**：Agent 执行过程中，用户看到什么？

**选项**：
- A：只显示最终结果
- B：显示每一步 Tool 调用和结果
- C：显示 Agent 思考过程 + Tool 调用 + 结果

**建议**：C。Agent Activity 是核心体验，用户需要看到 Agent 的思考过程。

---

### Q10：用户确认时机

**问题**：Agent 在哪些操作前需要用户确认？

**选项**：
- A：所有文件写入前都需要确认
- B：删除文件前需要确认
- C：都不需要确认，用户随时可以停止

**建议**：C。V1 信任 Agent 的操作，用户可以通过「停止」来干预。删除操作可以在后续版本添加确认。
