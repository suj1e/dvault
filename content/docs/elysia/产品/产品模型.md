# 产品模型

## 实体关系总览

```text
Device
  └── Workspace
       └── Session
            └── Task
                 └── Agent
                      └── Tool Execution
                           └── Events
```

---

## Entity 定义

### Device

**定义**：能执行 Coding Agent 的计算设备。

**V1 支持**：
- macOS（MacBook / Mac Studio / Mac mini）

**未来支持**：
- Linux Server

**属性**：
- `id`：设备唯一标识
- `name`：用户自定义名称
- `type`：设备类型（macOS / Linux）
- `status`：online / offline
- `capabilities`：该设备能做什么（文件系统、终端、Git 等）
- `currentSession`：当前活跃的 Session

**生命周期**：
- 用户首次启动 App 时创建
- 设备离线时 status 变为 offline
- 设备不删除（历史记录保留）

**用户操作**：
- 重命名设备
- 查看设备状态
- 选择设备执行 Session

---

### Workspace

**定义**：一个代码库的根目录。Agent 在此目录内操作文件。

**属性**：
- `id`：Workspace 唯一标识
- `name`：用户自定义名称
- `path`：本地绝对路径（macOS）或远程路径
- `deviceId`：所属 Device
- `language`：主要编程语言（自动检测或手动设置）
- `createdAt`：创建时间

**生命周期**：
- 用户在 macOS 上选择本地文件夹时创建
- 随 Device 删除而删除（V1 不跨设备迁移）

**用户操作**：
- 创建 Workspace（选择本地文件夹）
- 删除 Workspace
- 重命名 Workspace

---

### Session

**定义**：用户与 Agent 的一次持续交互。是 Agent 执行任务的核心上下文。

**属性**：
- `id`：Session 唯一标识
- `workspaceId`：所属 Workspace
- `deviceId`：创建/当前所在的 Device
- `title`：Session 标题（自动生成或用户自定义）
- `status`：idle / running / paused / completed / failed / stopped
- `createdAt`：创建时间
- `completedAt`：完成时间
- `task`：当前任务描述

**生命周期**：
1. 用户在某个 Device 的某个 Workspace 中创建 Session
2. Agent 开始执行 Task，status → running
3. 用户可以暂停（status → paused）或停止（status → stopped）
4. Agent 完成任务（status → completed）或失败（status → failed）
5. Session 变为历史，可 Resume 重新执行

**用户操作**：
- 创建 Session
- 发送消息
- 暂停 Session
- 停止 Session
- Resume Session（重新执行）
- 删除 Session
- 查看 Session 历史

---

### Task

**定义**：Session 中用户给出的具体任务描述。

**属性**：
- `id`：Task 唯一标识
- `sessionId`：所属 Session
- `description`：用户自然语言描述
- `status`：pending / in_progress / completed / failed
- `createdAt`：创建时间

**说明**：
- V1 中一个 Session 只有一个活跃 Task
- Task 的 description 就是用户在 Session 中输入的第一条消息
- Agent 执行过程中，用户可以追加消息，这些追加消息作为 Task 的补充输入

---

### Agent

**定义**：执行 Coding Task 的 AI 实体。

**属性**：
- `id`：Agent 唯一标识
- `sessionId`：所属 Session
- `model`：使用的模型（如 Claude Sonnet、GPT-4）
- `status`：thinking / acting / idle / stopped
- `startedAt`：启动时间
- `stoppedAt`：停止时间

**生命周期**：
1. Session 创建时 Agent 自动启动
2. Agent 循环执行：Understand → Plan → Act → Observe → Verify
3. Task 完成或用户停止时，Agent 停止

**用户操作**：
- 选择模型（V1 提供预设选项）
- 停止 Agent
- Resume Agent

---

### Tool Execution

**定义**：Agent 调用单个 Tool 的执行记录。

**V1 Tools**：
- `read_file`：读取文件内容
- `write_file`：写入/覆盖文件
- `list_files`：列出目录文件
- `search_code`：搜索代码内容
- `run_command`：执行终端命令

**属性**：
- `id`：执行记录唯一标识
- `sessionId`：所属 Session
- `toolName`：Tool 名称
- `input`：Tool 输入参数
- `output`：Tool 执行结果
- `status`：pending / running / completed / failed
- `startedAt`：开始时间
- `completedAt`：完成时间
- `error`：错误信息（status = failed 时）

**用户可见性**：
- 所有 Tool Execution 对用户可见
- 显示在 Agent Activity 面板中
- Diff 类型（write_file）显示代码变更

---

### Events

**定义**：系统状态变化的通知。用于多端同步和实时 UI 更新。

**生命周期**：
- 由 Agent Runtime 发出
- 通过 Event Bus 分发给订阅的客户端
- 客户端根据 Event 更新本地 UI

详见 [[../开发/事件系统|事件系统]]。

## 实体关系

| 关系 | 说明 |
|------|------|
| Device 1:N Workspace | 一个设备可以有多个 Workspace |
| Workspace 1:N Session | 一个 Workspace 可以有多个历史 Session |
| Session 1:1 Agent | 一个 Session 同时只有一个 Agent |
| Session 1:N Tool Execution | 一个 Session 包含多次 Tool 调用 |
| Session N:M Device | 一个 Session 可在多个 Device 上查看（但执行在一个 Device 上） |

## V1 推迟的实体

| 实体 | 原因 |
|------|------|
| Project Settings | V1 不涉及复杂项目配置 |
| Team / Organization | V1 是个人产品 |
| Billing | V1 不考虑 |
| User Profile（跨设备） | V1 不要求账户系统 |
| Plugin / Extension | V1 不开放 |
| Memory / Knowledge Base | V1 不引入长期记忆 |
| Sub-Agent | V1 单 Agent |
| Workflow | V1 单 Task 线性执行 |
