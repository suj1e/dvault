# 异常与边界

## Agent 执行异常

### 场景 1：Tool 执行失败

**触发条件**：文件不存在、权限不足、命令执行返回非零退出码

**处理**：
1. Agent 收到 error 结果
2. Agent 分析错误原因
3. Agent 自动 Retry（最多 3 次）
4. Retry 失败：
   - Agent 向用户报告错误
   - 提供可选方案
   - 等待用户决策

**用户可见**：Tool Execution 状态变为 failed，显示错误信息

---

### 场景 2：Agent 无限循环

**触发条件**：Agent 反复执行相同或类似的 Tool，无法推进任务

**处理**：
1. 系统检测到相同 Tool 连续执行 N 次（如 5 次）
2. Agent 自动停止，状态变为 failed
3. 向用户报告："Agent 似乎陷入循环，请提供更多信息"
4. 用户可以 Resume 或重新开始

**用户可见**：Session 状态变为 failed，显示循环检测警告

---

### 场景 3：用户中途停止 Agent

**触发条件**：用户在 Agent 执行过程中点击「停止」

**处理**：
1. Agent 立即停止当前 Tool 执行
2. 保留当前状态（已修改的文件、已执行的部分）
3. Session 状态变为 stopped
4. 发出 `agent.stopped` Event

**用户可见**：Session 状态变为 stopped，可以 Resume

**Resume 行为**：
- 从停止点继续执行
- Agent 可以看到之前的上下文
- 用户可以提供新的指令

---

### 场景 4：网络断开

**触发条件**：客户端与服务端连接断开

**处理**：
1. 客户端显示"连接断开"
2. 客户端尝试自动重连（指数退避）
3. 重连成功后，客户端发送最后收到的 Event ID
4. 服务端补发缺失的 Event
5. UI 恢复实时状态

**用户可见**：短暂显示"连接断开"，重连后自动恢复

---

## 设备异常

### 场景 5：Device 离线

**触发条件**：macOS App 关闭或网络断开

**处理**：
1. Device 状态变为 offline
2. 正在运行的 Session 暂停（如果 Session 依赖该 Device 执行）
3. iOS / Web 端显示 Device 离线
4. Device 重新上线后，Session 可以 Resume

**用户可见**：Device 列表中显示 offline，Session 显示暂停状态

---

### 场景 6：Device 丢失

**触发条件**：用户更换设备或卸载 App

**处理**：
1. Device 长期未上线（如 30 天）
2. 系统标记 Device 为 inactive
3. 保留 Device 和 Session 历史（只读）
4. 用户可以手动删除 Device

**用户可见**：Device 列表中显示 inactive，可以查看历史但无法执行新 Session

---

## 文件系统异常

### 场景 7：文件被外部修改

**触发条件**：用户在 Agent 执行过程中，用其他编辑器修改了文件

**处理**：
1. Agent 读取文件时检测到修改时间变化
2. Agent 报告："文件已被外部修改，是否继续？"
3. 等待用户决策

**V1 措施**：
- 不监听文件系统变化
- Agent 只在需要时读取文件
- 如果读取结果与预期不符，Agent 报告问题

---

### 场景 8：Workspace 被删除或移动

**触发条件**：用户删除或移动了 Workspace 文件夹

**处理**：
1. Agent 执行时发现路径不存在
2. Agent 报告错误："Workspace 路径不存在"
3. Session 状态变为 failed
4. 用户在 App 中更新 Workspace 路径或重新创建

---

## Session 异常

### 场景 9：Session 历史过多

**触发条件**：Workspace 下有大量历史 Session

**处理**：
1. V1 不限制 Session 数量
2. 客户端实现分页加载
3. 用户可以删除不需要的 Session

**V1 不做的**：
- 自动归档旧 Session
- Session 过期策略

---

## 边界情况

### 边界 1：空 Workspace

**场景**：用户选择了一个空文件夹作为 Workspace

**处理**：
- 允许创建
- Agent 可以执行（但可能没有太多可操作的内容）
- Agent 可以创建新文件

---

### 边界 2：超大文件

**场景**：Workspace 包含超大文件（如 100MB 的二进制文件）

**处理**：
- Agent 的 `read_file` 只读取文本文件
- 二进制文件返回错误："无法读取二进制文件"
- `list_files` 列出文件名，不读取内容

**V1 不做的**：
- 文件类型过滤
- 大文件警告

---

### 边界 3：极长输出

**场景**：`run_command` 执行命令产生极长输出（如 10000 行日志）

**处理**：
- 截断输出（如前 1000 行 + 后 1000 行）
- 提供"查看完整输出"选项
- 标记输出被截断

---

### 边界 4：Agent 执行超时

**场景**：Agent 执行 Task 超过预定时间

**处理**：
- V1 不设置硬超时
- 用户可以随时停止
- 如果 Agent 长时间无响应，用户感知为"卡住"，点击停止

---

## 数据一致性

### 场景 5：多端消息冲突

**场景**：用户在 macOS 和 iOS 同时发送消息

**处理**：
1. 服务端按时间顺序接收消息
2. 按顺序加入 Session 消息队列
3. Agent 按顺序处理
4. 如果消息之间有冲突（如"做 A"和"不要做 A"），Agent 最后收到的消息优先

**V1 不做的**：
- 消息锁定
- 冲突检测
- 消息撤销
