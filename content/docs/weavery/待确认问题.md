## Q1

**铃铛未读数硬编码**

顶栏铃铛 `aria-label="通知,3 条未读"` 写死,但浮窗通知列表里实际只有 2 条 `.is-unread`,文案与数据不一致。

- 涉及:全站顶栏(见 [[全局规范#全站顶栏]])
- 影响:屏幕阅读器播报错误的未读数;真实数据下计数不可信
- 建议:未读数应由通知列表数据驱动,不硬编码

## Q2

**数字单位"万"与"k"混用**

同一站点内两套数字格式并存:卡片浏览数 / 点赞数用"万"(`fmt()` 规则 ≥10000 → "X.X 万"),而讨论统计(`discuss-stats`)、侧栏话题热度、推荐作者粉丝数用"k"(如 9.6k / 12.4k)。

- 涉及:全站(见 [[全局规范#数字格式化]])
- 影响:单位不统一,读者需心算换算;i18n 与统计口径混乱
- 建议:统一为一种单位制(中文社区建议统一"万"),或按语境明确分工

## Q3

**⌘B 加粗未实现**

工作台文档区工具栏提示"支持 Markdown · ⌘B 加粗",但全页 `keydown` 只绑定了 ⌘K 聚焦搜索,没有捕获 ⌘B,也没有对选区做 `**` 包裹的逻辑。

- 涉及:[[功能/AI写作工作台#文档区工具栏]]
- 影响:快捷键承诺与实现不符
- 建议:M1 明确——要么实现 ⌘B 包裹,要么移除提示文案

## Q4

**工具栏格式按钮无交互**

文档区工具栏 6 个按钮(加粗 / 斜体 / 引用 / 无序列表 / 链接 / 插图)都是裸 `<button>`,无 `click` handler,富文本格式化在原型里纯视觉占位。且缺有序列表、标题、代码块、分割线、撤销/重做。

- 涉及:[[功能/AI写作工作台#文档区工具栏]]
- 影响:开发时若按原型照搬,格式化全部不可用
- 建议:明确工具栏 M1 范围(是否实现 Markdown 包裹式格式化、按钮全集)

## Q5

**斜杠命令无弹出菜单**

工作台系统消息写"输入指令或点击下方 /命令",暗示存在可点击的命令芯片,但 HTML 里没有任何命令入口。输入 `/` 不会弹出建议列表,只对消息首 token 做全等匹配(`/润色` `/续写` `/标题` `/摘要`)。

- 涉及:[[功能/AI写作工作台#斜杠命令]]
- 影响:引导文案与 UI 不符;无自动补全体验
- 建议:二选一——补充斜杠命令弹出菜单,或修改引导文案去掉"点击下方 /命令"

## Q6

**模型清单不一致**

工作台 `MODELS = ["GPT-4o", "Claude 4", "DeepSeek-V3", "通义千问"]`,设置页个性化默认模型选项为"GPT-4o / Claude 3.7 / 本地模型 · 仅限已配置"。两处模型名与集合都不一致。且工作台是循环点击 pill,设置页是 select 下拉。

- 涉及:[[功能/AI写作工作台#写作配置]] · [[功能/账户与治理#个性化]]
- 影响:同一产品两套模型清单,用户困惑;数据契约无法对齐
- 建议:统一模型清单(名称与版本),明确工作台与设置页的选项关系

## Q7

**话题发帖未透传话题标签**

话题页"发帖"按钮 `location.href = "create.html"`,没有带上 `?t=` 参数,工作台不会预填该话题标签。文档曾描述"发帖预填话题标签"。

- 涉及:[[功能/话题与搜索#话题页]]
- 影响:从话题进入发帖无法自动归属话题,需手动补标签
- 建议:发帖按钮透传 `create.html?t={话题}`,工作台识别并预填

## Q8

**话题排序对"万"单位失真**

话题页"讨论最多"排序用 `parseInt(views)` 比较,但浏览数可能是"1.2 万"格式,`parseInt` 得到 1,导致排序错误。

- 涉及:[[功能/话题与搜索#话题页]]
- 影响:按讨论量排序结果错误
- 建议:排序前统一把"万/k"还原为数值再比较

## Q9

**空话题无空状态 UI**

`职业成长 / 生活 / 翻译 / 写作 / 生成式设计` 5 个内置话题 `posts` 为空,但话题页未提供空状态,会渲染空白列表。

- 涉及:[[功能/话题与搜索#话题页]]
- 影响:进入空话题看到空白,无引导
- 建议:补充话题空状态(如"这个话题还没有内容,去工作台写第一篇")

## Q10

**移动端侧栏直接消失无降级**

`<1020px` 时 `.sidebar { display: none }`,话题页的"相关话题""话题规则"、feed 页的侧栏在平板/手机上完全消失,没有移到底部或折叠的降级方案。

- 涉及:[[功能/话题与搜索]] · [[功能/信息流]]
- 影响:窄屏丢失话题规则等治理信息与发现入口
- 建议:移动端把关键侧栏内容(话题规则、热门话题)降级到正文流中或可展开抽屉

## Q11

**话题数实为 19,旧文档记 17**

原型内置话题实为 **19 个**,旧文档记为"约 17",且把"开源与商业化"误写为"开源商业化"。补全时已修正为 19 并核对名称。

- 涉及:[[功能/话题与搜索#内置话题]]
- 状态:**文档已修正**(见话题完整清单表)
- 建议:开发时以 19 个为准,数据源核对名称

## Q12

**草稿删后累计字数不联动**

草稿箱删除一条草稿后,`updateStats()` 重算了"全部草稿""AI 辅助创作"两项,但"累计字数"(`stat-words`)未重算。

- 涉及:[[功能/创作者中心#草稿箱]]
- 影响:删稿后累计字数错误
- 建议:统计联动应覆盖全部三项

## Q13

**草稿载入路由不一致**

me 页内嵌草稿的"继续编辑"跳 `create.html`(无参数),drafts 页跳 `create.html?draft={id}`。两处载入草稿的路由不统一。

- 涉及:[[功能/创作者中心#我的]] · [[功能/创作者中心#草稿箱]]

## Q14

**help 实为完整 FAQ(旧文档误记为占位)**

help 页实际有完整内容:5 个分类共 13 条 FAQ(快速上手 4 / AI 写作 3 / 社区与话题 3 / 账号与隐私 3)+ 联系支持(反馈表单 + 邮箱 `support@weavery.example`)。旧文档误记为"占位,待完善"。

- 涉及:[[功能/账户与治理#帮助中心]]
- 状态:**文档已修正**(见帮助中心章节的真实 FAQ 结构)
- 建议:开发时按完整 FAQ 实现,勿当占位

## Q15

**owner 模式无后端校验**

帖子详情的作者专属操作(编辑/删除)通过 `/[?&]owner=1/.test(location.search)` 纯前端判断,无后端权限校验。

- 涉及:[[功能/帖子详情与Remix#作者专属操作]]

## 第二轮:边界场景待定项

## Q21

**文章字数上限**

工作台正文未设字数上限,但实际发布需有上限(影响存储、阅读时长计算、feed 摘要截断)。

- 涉及:[[功能/AI写作工作台]] · [[异常与边界#D1]]
- 影响:无法实现字数超限校验;阅读时长对超长文失真
- 建议:明确上限(如 5 万字),超限阻止/提示

## Q22

**标题 / 评论 / 私信长度上限**

已知昵称 maxlength 20,但文章标题、评论、私信的长度上限均未定义。

- 涉及:[[异常与边界#D2]]
- 影响:无法做输入校验;长文本可能破坏布局
- 建议:分别设上限(如标题 100、评论 2000、私信 5000)

## Q23

**图片上传大小 / 格式限制**

工作台插图、私信插图、封面图的上传约束未定义。

- 涉及:[[异常与边界#D3]]
- 影响:无法实现上传校验;超大文件影响体验与存储
- 建议:明确大小(如 ≤5MB)、格式(image/\*)、尺寸、是否压缩

## Q24

**注销级联策略(全删 vs 匿名化保留)**

注销冷静期到期永久删除时,用户的文章 / 评论 / 收藏如何处理——全部物理删除,还是匿名化保留(评论显示"已注销用户")。

- 涉及:[[异常与边界#E2]]
- 影响:影响数据完整性、他人评论的上下文、社区内容连续性
- 建议:采纳匿名化保留(文章可保留但作者标"已注销",或提供"保留/删除"选项)

## Q25

**被封禁用户内容可见性**

账号被封禁后,其已发布内容是保留可见、隐藏、还是删除。

- 涉及:[[异常与边界#E3]]
- 影响:影响社区内容完整性与治理力度
- 建议:明确策略(如:内容保留但账号标"已封禁";严重违规才删内容)

## Q26

**被限制功能用户的限制范围**

guidelines 第 7 条"重复违规限制账号功能",具体限制哪些功能(发布?评论?点赞?)未定义。

- 涉及:[[异常与边界#E4]] · [[功能/账户与治理#执行分级与申诉]]
- 影响:无法实现限制态的权限控制
- 建议:明确限制维度与时限(如禁言 7 天 = 不可发布/评论,可浏览/点赞)

## Q27

**AI 用量配额机制**

dashboard 的"AI 创作用量"(326)是否有上限、如何重置、按模型还是总量计、超额如何处理,均未定义。

- 涉及:[[异常与边界#A5]] · [[功能/创作者中心#四项-kpi]]
- 影响:无法实现配额控制;商业模式(免费/付费)无法落地
- 建议:明确配额(如免费版每日 N 次)、重置周期、超额引导

## Q28

**AI 模型下线的标注策略**

历史文章用的 model(如某退役模型)下线后,文章的 model-tag 如何显示。

- 涉及:[[异常与边界#F3]]
- 影响:历史 AI 内容的透明度信息缺失
- 建议:model-tag 保留原值并标注"已退役",不影响阅读

## Q29

**多端编辑并发(乐观锁 vs 覆盖)**

作者多端同时编辑同一文章时,采用乐观锁(Post.version,后提交者 409)还是直接后写覆盖。

- 涉及:[[异常与边界#C2]] · [[数据模型#文章-post]]
- 影响:数据丢失风险;UX 复杂度
- 建议:采纳乐观锁 + 冲突提示,避免静默丢失

## Q30

**AI 作者管理后台**

原型是消费侧展示页,未体现 AI 作者管理后台。需要确认:是否单列管理后台、是否纳入 M1、后台覆盖哪些功能(AI 作者账号管理、调度任务配置、审校队列、发布历史与驳回记录)。

- 涉及:[[AI作者与内容生产#六、管理后台待建]]
- 影响:无法配置 AI 作者、调度、审校;`auto`/`manual` 模式无法运营
- 建议:至少提供配置 + 审校队列两个核心界面(见 [[数据模型#ai-作者管理-aiauthor]] 端点)

## Q31

**审校时效与超时策略**

`manual` 审核模式下,生成的任务进审校队列后,若策展人长时间未处理,系统如何应对(仅提醒 / 超时自动转 `auto` 发布 / 转人工兜底),以及超时阈值均未定义。

- 涉及:[[AI作者与内容生产#四、审核模式核心]]
- 影响:`manual` 模式下内容可能积压,影响"定时定期"的发布节奏
- 建议:设定审校 SLA(如 24h),超时仅提醒不自动发布(避免低质内容泄漏)

## Q32

**策展人角色定义**

策展人(Curator)是 `User.role` 的独立枚举值(如新增 `curator`),还是复用 `human` + 权限位/管理员子角色?

- 涉及:[[权限矩阵#角色]] · [[数据模型#用户-user]]
- 影响:`User.role` 枚举与鉴权实现;管理员/策展人权限边界
- 建议:复用 `human` + 独立权限位(如 `is_curator`),避免污染 role 枚举

## Q33

**"经人工修订"标记是否落库**

`manual` 模式下策展人改稿后,是否在 `Post` 落库为独立字段(如 `human_revised` bool),还是仅在 UI 展示?数据模型 `Post` 实体当前无此字段。

- 涉及:[[AI作者与内容生产#四、审核模式核心]] · [[数据模型#文章-post]]
- 影响:影响透明度信息完整度(读者能否区分"纯 AI"与"AI + 人工修订")
- 建议:落库 `human_revised` 字段,UI 显示"基于 AI 生成 · 经人工修订",保持透明度
